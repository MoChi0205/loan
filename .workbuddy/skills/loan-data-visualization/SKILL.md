# 数据统计与图标规范

## 目标

- 统计图必须服务于角色决策：客户、顾问、团队管理、运营、老板、超级管理员、渠道只展示其数据范围。
- 10 万客户场景禁止把明细全量下发给前端；图表接口只返回聚合结果、分页明细或 Top N。
- 图标使用项目 `AppIcon` 单一入口，禁止页面直接混用 emoji、字体图标和多个图标库。

## 图表交互

- 首屏优先展示指标卡、趋势、待办；避免同屏超过 6 个视觉焦点。
- 每个图表必须有标题、统计口径、时间范围、加载态、空态、错误态和更新时间。
- 数值使用中文业务文案，不向用户展示内部客户 ID、报告 ID、审批 ID。
- 图表颜色使用设计令牌；状态色固定：成功绿色、处理中蓝色、待审批橙色、失败红色。
- 移动端使用横向滚动或分段切换，文字不换行；触控目标至少 44px。

## 性能约束

- 后端按时间、团队、归属顾问聚合，优先 SQL `COUNT/SUM/GROUP BY`，禁止 `selectList()` 后在 Java 内存统计 10 万行。
- 明细接口统一分页，默认 20、最大 100；趋势默认最多 31 个时间桶；排名默认 Top 10。
- 相同筛选条件的统计结果使用 Caffeine 本地缓存，跨实例使用 Redis；写入客户、分配、审批后按业务域失效。
- 图表组件使用 ECharts 按需引入或轻量 SVG，禁止全量引入图表包。

## 实现检查

1. 先确认接口是否返回聚合数据和统计口径。
2. 再确认角色权限和数据范围在后端执行。
3. 复用 `AppIcon`、`AppEChart`、设计令牌，不复制图标 SVG。
4. 验证空数据、慢接口、10 万数据量下分页与缓存命中。
