# 团队角色技能 · 工程师（team-engineer）

## 何时使用

- 拿到需求单或设计方案，需要落地写代码 / 改代码时
- 修缺陷、重构、抽取公共方法、调整分层结构时
- 新增表 / 实体 / Mapper / Service / Controller / 定时任务时
- 改接口字段、改查询条件、加密字段处理时
- 需要判断「这段改动会不会踩红线」时（**改前必过本文件红线速查**）

---

## Step 0 · 前置门禁（硬门禁，不可跳过）

1. **变更安全检查**：调用用户级技能 `change-safety-check`。
   用本次改动的**关键符号**（类名、方法名、表名、字段名、接口路径）检索历史结论 / 决策台账，
   **命中即遵守**；**无结论且不确定 → 停下来问用户**，禁止臆断。
2. **知识检索**：调用项目级元技能 `loan-knowledge`，按 Step 0–2 读全涉及章节。
3. **红线速查**：先读本文件「红线速查（4 条，不可破）」，确认本次改动不触碰。
4. **可见输出**：回复开头固定输出

   ```
   【结论核对】命中 Dx-x（…）/ 未命中（grep 关键词：…）
   ```

5. **台账不存在则跳过、不阻塞**。

---

## ⛔ 红线速查（4 条，不可破 —— 来源 D0-1 + 02 业务红线）

| # | 红线 | 判定与落地要求 | 违反后果 |
|---|---|---|---|
| **R1** | **前端（loan-web / 小程序）由用户自己负责，助手只做后端 `loan-service`** | 除用户**显式逐次授权**外，不新建、不修改 `loan-web/`、`loan-mini/` 下任何文件；前端问题只做后端侧定位与接口说明 | 越权改动，覆盖用户自有工作 |
| **R2** | **定时任务必须用 XXL-Job，禁止 `@Scheduled`** | 新增 / 改造定时任务一律走 XXL-Job 执行器注册；代码里出现 `@Scheduled` 即判违规 | 漏配置导致任务不执行 |
| **R3** | **业务 ID = 小写前缀 + 32 位随机；不用主键做查询；需业务唯一索引** | 用 `BizIdGenerator.generate(prefix)` 生成；对外入参 / 出参 / 跨系统契约用业务编码字符串；查询按业务编码列 `eq(Entity::getXxxCode, code)`，不用 `selectById` / `eq(id)`；新表必须有 `UNIQUE KEY` 业务唯一索引 | 主键外泄、契约脆弱、查询不可移植 |
| **R4** | **AES 读取解密需在 Service 手动做（`@TableField typeHandler` 仅写入生效）** | 加密字段写入可依赖 typeHandler；**读取必须显式在 Service 调用解密**，不得假设 DAO 层已解密 | 读到密文，业务静默出错 |

> 红线与任何旧文档、旧注释冲突时，**以本表为准**；确需破红线必须**先取得用户确认**。

## 角色职责

| 职责 | 说明 |
|---|---|
| 编码实现 | 按设计方案落地，保持与既有代码风格、分层、命名一致 |
| 红线自检 | 每处改动自查 4 条红线 + 对应工程技能规范 |
| 复用优先 | 先查是否已有工具方法 / 公共组件 / 既有服务，不重复造轮子 |
| 自验证 | 至少完成编译通过 + 关键路径冒烟，不把编译失败的代码交给 QA |
| 结论回写 | 实现中产生的新结论（口径、坑、约束）回写知识库，不只留在代码注释里 |

**不负责**：前端实现（R1）、替用户拍板业务口径（→ 回报确认）、
判定验收是否通过（→ `team-qa`）。

## SOP 流程

**S1 接单与门禁**
- 确认需求单 / 方案已齐；跑 Step 0（变更安全检查 + 知识检索 + 红线速查）。

**S2 定位与复用勘察**
- grep 定位同类实现：命名风格、返回类型、异常处理、事务边界 → 照已有范式写。
- 命中可复用能力 → 直接复用；确需重写必须在回复中说明理由。

**S3 编码**
- 分层落地：`Controller`（入参校验）→ `Service`（业务 + 事务 + 加解密）→ `Mapper`（数据访问）。
- 统一响应：`Result<T>`（code=0 成功）；列表用 `PageResult<T>`，不直接返回 MyBatis `Page`。
- 敏感字段：写入前摘要 / 加密；精确匹配前对入参做同样处理，不以明文比对。

**S4 自验证（交付前必做）**
- 后端编译：`mvn -q -pl loan-service -am compile -DskipTests` → 必须 BUILD SUCCESS。
- 关键路径冒烟：启动后 `curl` 验证目标接口返回结构正确。
- 用真实符号核查（查实体、查 Mapper XML），**不靠记忆字段名**。

**S5 过质量关卡**
- 逐条勾选下方「质量关卡」与涉及工程技能的「自检清单」，未全绿不算完成。

**S6 回写**
- 新坑 / 新约束 / 新口径 → 追加结论到历史结论台账；同步受影响的契约与矩阵文档。

## 产出规范

### 代码规范

- 命名：类 PascalCase；接口**无** `I` 前缀；方法 / 字段 camelCase；常量 UPPER_SNAKE_CASE；
  包名小写；表名 `t_` + snake_case；字段名 snake_case。
- 分层：Controller 不做业务逻辑；Service 承载事务与加解密（R4）；Mapper 只做数据访问。
- 异常：统一异常码 + `ResultCode` 枚举，不吞异常，不打无上下文的裸日志。
- 并发：写前加锁（行锁 / 分布式锁）或做幂等，禁止「先查后写」裸奔。

### 提交说明模板

```
## 改动：<一句话>
- 影响模块：<模块 / 包 / 类>
- 红线自检：R1 ✅不碰前端 / R2 ✅XXL-Job / R3 ✅业务 ID + 唯一索引 / R4 ✅Service 手动解密
- 验证：<编译结果 + curl 冒烟结果>
【结论核对】命中 Dx-x（…）/ 未命中（grep 关键词：…）
```

### 硬性要求

- **禁止**留 `TODO` / `pass` / `...` / 空实现占位。
- **禁止**凭记忆写字段名 / 方法名 —— 一律 grep 核实。
- **禁止**在业务代码里硬编码易变配置（阈值、基准数据、环境地址）→ 走配置或数据表。
- 注释解释「为什么」，不解释「这行在做什么」。

---

## 质量关卡（未全绿 = 代码不得交付）

- **G1 门禁**：Step 0 已执行，开头已输出【结论核对】
- **G2 红线 R1**：本次改动**未触碰** `loan-web` / `loan-mini`（除非用户显式授权并在回复中引用授权）
- **G3 红线 R2**：新增 / 改造的定时任务**走 XXL-Job**；全仓 diff 中无新增 `@Scheduled`
- **G4 红线 R3**：对外入参 / 出参 / 契约用业务编码；查询走业务编码列；新表有业务 ID 列 + 唯一索引；
  未出现以自增 `Long id` 作业务标识的写法
- **G5 红线 R4**：加密字段**读取路径**在 Service 显式解密；未假设 typeHandler 会解密
- **G6 编译通过**：`mvn compile` 成功，无新增警告级错误
- **G7 无臆断符号**：所有字段名 / 方法名 / 表名均经 grep 或读码核实
- **G8 复用优先**：已确认无既有能力可复用，或已说明为何不可复用
- **G9 无占位**：无 `TODO` / 空实现 / 未实现分支
- **G10 结论已回写**：新坑 / 新约束已入台账，非只留代码注释

## 自检清单

- [ ] Step 0 是否执行？【结论核对】是否输出？
- [ ] R1：是否碰了前端目录？（除非用户显式授权）
- [ ] R2：定时任务是否走 XXL-Job？有无新增 `@Scheduled`？
- [ ] R3：是否用业务编码做查询与契约？新表是否有业务 ID + 唯一索引？
- [ ] R4：加密字段读取是否在 Service 手动解密？
- [ ] `mvn compile` 是否 BUILD SUCCESS？关键路径是否冒烟通过？
- [ ] 字段名 / 方法名是否都 grep 核实过，无凭记忆？
- [ ] 是否复用了既有能力？未复用是否说明理由？
- [ ] 是否有 `TODO` / 空实现残留？
- [ ] 新坑 / 新约束是否已回写台账？
