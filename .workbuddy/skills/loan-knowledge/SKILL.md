# loan-main 知识治理元技能（loan-knowledge）

## 何时使用

- **任何**涉及 loan-main 的需求分析、方案设计、编码、评审、修改、调整、删除任务**开始前**
- 需要业务背景、历史决策、字段口径、角色边界、复用映射时
- 想凭「我记得 / 我猜 / 应该是」直接改代码或删文件前 —— **先读本文件**
- 生成需求 / 计划 / 设计 / 会议纪要 / 结论文档，想把文档「先放桌面或 /tmp」时 —— **先读本文**
- 被其它 `loan-*` 工程技能的 Step 0 引用时（本技能是它们的强制前置）

## Step 0 · 前置门禁（硬门禁，不可跳过）

1. **先查历史结论**：用本次需求关键词 `grep -n "<关键词>" docs/knowledge-base/10-历史结论与决策日志.md`，
   从**最新条目往下**读（该台账按时间倒序，最新在最上方）。
   > ⚠️ **取号纪律（不可绕过）**：需要写入或引用具体 D 编号时，**必须自己刚跑完**
   > `grep -o "^| D[0-9-]*" docs/knowledge-base/10-历史结论与决策日志.md`，以**该次的实时输出**取号。
   > **禁止**采信：设计文档分配表 ❌、他人报告 ❌、team-lead 广播 ❌、自己的记忆 ❌。
   > 本文件刻意**不写死"当前是 Dxx"**——任何写死的数字都会在下一次并发写入后立刻过期。
2. **命中即以其为准**：与任何旧文档、旧技能描述冲突时，**D 条目优先级最高**。
3. **核对「状态」列**：状态为「已被 Dxx 替代」的条目**跳过、改读 Dxx**（D 系列只追加不删除，原条目保留供追溯）。
4. **无结论且不确定 → 停下来问用户**，**禁止臆断**（对应 10-日志 头部纪律：「有结论 → 直接遵守；无结论且不确定 → 停下来问用户」）。
5. **文件不存在则跳过本步，不阻塞**（保证本技能在其它仓库也可用）。
6. 在回复开头输出「结论核对」小结，格式固定：
   ```
   【结论核对】命中 D0-4（ALLOCATION 审批不含 DEPT_MANAGER）/ 未命中（grep 关键词：审批,分配,ALLOCATION）
   ```
7. **命中且与本次需求冲突 → 先向用户确认再动手**，不擅自推翻历史结论。

## 文档归档规范（已吸收原 `document-archiving` 全部规则）

### 核心原则：唯一真源 + 分类归档 + 简体中文

**禁止**

- ❌ 把项目文档散落到 `/tmp`、`/notes`、桌面、仓库根目录等任意位置
- ❌ 在多个位置创建重复 canonical 副本
- ❌ 只把重要项目决策留在聊天记录中，不落库
- ❌ 说明性文本用英文（除非原始材料为英文，需总结为中文）

**应该**

- ✅ **唯一真源**：项目规划 / 需求 / 设计 / 决策的 canonical source 是知识库，不是临时聊天输出
- ✅ **分类归档**：按文档类型放入对应子目录
- ✅ **简体中文**：知识库说明性文本、摘要、分析、决策、日志一律简体中文；
  代码符号 / 类名 / 方法名 / 表名 / 枚举值 / 命令可保留原文
- ✅ **持久记录**：重要新知识写回知识库，不随会话消失

### 归档分类

| 文档类型 | 位置 |
|---|---|
| 需求 / PRD / 规格 / 用户故事 | `requirements/` |
| 计划 / 设计 / 实施 / 架构 | `docs/plans/` |
| 研究 / 调研 / 对比 | `research/` |
| 会议纪要 / 决策记录 | `docs/`（本项目纪要落 `docs/`） |
| 外部文章 / 指南 / 参考 | `articles/` |
| 图片 / 图表 / 附件 | `assets/` |
| 项目长期记忆（结论台账） | `docs/knowledge-base/` |
| 工程规范技能 | `.workbuddy/skills/`（**唯一加载路径**） |
