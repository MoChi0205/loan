## 一、项目背景

你正在协助一个贷款业务系统 `loan-main` 的前端重构收尾。此前已完成一套跨端统一设计系统「墨金 Ink & Gold」的设计与确认，但**尚未落地到源码**。你的任务：基于下面给出的「已完成的、已确认归档的设计系统」事实，撰写一份「把设计系统落地接入两端前端源码」的**待处理事项清单（TODO）**，供开发团队按顺序执行。

## 二、项目结构（仅列与本次相关的部分）

- `loan-web`：Vue3 + Element Plus + Vite 的 **Web 管理端**（真前端）。
- `loan-mini`：uni-app（Vue3）**微信小程序**（真前端）。
- `loan-service`：Java 后端（Spring Boot + dubbo + nacos），**不是前端，排除在任务之外**。

## 三、已完成的、已确认归档的设计系统（输入事实，不要重新设计）

设计系统交付物位于 `docs/design-system/`，包含：

1. `DesignSystemManifest.md`：统一语义设计令牌。配色——深墨蓝 `#16203A`（主承载/信任感）、暖金 `#D9A441`（唯一价值强调色）；**明暗双主题映射**：Web 端以暗色为主，Mini 端以浅色为主。原 web 令牌 `--loan-*` 与原 mini 令牌 `--brand-*` 互不连通，现统一为一套语义令牌。字体：西文 `Space Grotesk`、中文 `Noto Sans SC`。另含间距标尺、圆角、阴影、图标规范。
2. `ComponentSpec.md`：组件清单与各状态（default/hover/active/focus/disabled/loading/error）。
3. `QAReport.md`：质量检查已通过，含 3 条 P2 级建议。
4. `DeveloperGuide.md`：Web / Mini 落地步骤、旧图标名 → 新图标名映射、Mini 颜色脱钩方案。
5. `code/icons.js`：36 枚原创线性 SVG 图标路径，作为**单一事实来源**（统一 24×24、线宽 1.75、圆角端点、`currentColor`）。
6. `code/AppIcon.web.vue`：Web 图标组件，支持 `var()` 随主题联动。
7. `code/AppIcon.mini.vue`：Mini 图标组件，运行时注入真实色值（THEME 对象），修复小程序 SVG 不解析 `var()` 导致图标颜色写死 `#2443C2`、换肤失效的历史 bug。
8. `prototype/design-showcase.html`：可交互原创图预览。

## 四、已知痛点（待处理清单必须正面解决）

- **Web 端**：图标三套来源混用（自建 AppIcon / Element Plus 内置图标 / 散落在 **23 个 .vue 文件**里的手写内联 `<svg>`，尺寸 12/14/16/18/20、线宽 1.7/1.8/2/2.4 混乱）；`src/styles/index.css` 约 **1157 行**含大量硬编码 hex 与令牌重复。
- **Mini 端**：图标颜色写死、换肤不联动；无暗黑模式；`--brand-*` 与 web 令牌不连通。

## 五、任务要求（请输出一份待处理事项清单）

1. 覆盖把上述设计系统落地到 `loan-web` 与 `loan-mini` 源码的全过程。
2. 建议按三段组织：**A = loan-web、B = loan-mini、C = 双端验收**，每段用可勾选条目（`- [ ]`）。
3. 清单需包含：背景目标、范围与边界、验收标准、关键风险 / 注意事项。
4. **不改动**业务逻辑、接口、路由结构；仅做样式令牌化、图标统一、字体 / 主题。
5. 给出可执行的验收标准（例如：换肤仅改一处、图标全部来自单一来源、无游离 hex、零回归）。
6. 请只输出待处理事项清单本身（可参照上述结构），不要重复设计系统的详细内容。
