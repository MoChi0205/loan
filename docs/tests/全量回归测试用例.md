# 全量回归测试用例

范围：`loan-service`、`loan-gateway`、`loan-web`、`loan-mini`（H5 / 微信小程序）。测试数据只在所选开发环境创建，基础设施连接以 Nacos 当前配置为准。

## 环境与身份

| 项目 | 当前基线 |
|---|---|
| Web | `http://localhost:9173` |
| H5 | `http://localhost:9174` |
| 网关 / 服务 | 9088 / 9080，上下文 `/loan` |
| 配置 | 显式 Nacos 地址和命名空间，group `loan`；不回退本地中间件 |
| 角色 | 客户、渠道、顾问、部门经理、老板、运营、超级管理员 |

## 角色、菜单与按钮

| 用例 | 操作 | 预期 |
|---|---|---|
| AUTH-001 | Web 各角色使用验证码、账号密码登录并退出 | 登录成功；验证码为随机字母数字；退出后 token 失效 |
| AUTH-002 | Web 使用验证码找回密码 | 校验手机号、验证码时效和不可重放；日志不含明文 |
| AUTH-003 | 小程序使用微信一键登录和验证码登录 | 不出现密码找回；微信身份与客户档案正确绑定 |
| MENU-001 | 各角色加载菜单并直达无权路由 | 无空父菜单；菜单、按钮、接口和数据范围一致；越权拒绝 |
| BUTTON-001 | 创建、审批、导出、下载、删除、分配 | 按权限执行；重复提交幂等；页面不显示内部业务 ID |

## 客户与服务运营

| 用例 | 操作 | 预期 |
|---|---|---|
| CLIENT-001 | 顾问查看、筛选和编辑本人客户 | 仅本人已归属客户可写；手机号脱敏；公司公海需先认领 |
| CLIENT-002 | 经理切换本人和本部门 | 不读取其他部门；本人、团队客户和团队公海范围正确 |
| CLIENT-003 | 公司级角色切换本人、本部门和全公司 | 筛选条件和统计随范围变化；渠道完全排除 |
| SERVICE-001 | 客户发起或员工代客创建四种预约 | 可不关联客户；代客创建直接确认；时间、方式、地点和来源正确 |
| SERVICE-002 | 距开始 5 分钟以上改期或取消 | 允许并留痕；不足 5 分钟拒绝普通操作 |
| SERVICE-003 | 提交、审批外出并完成两次打卡 | 可不关联客户；禁止自审；两次照片和单点位置必填 |
| SERVICE-004 | 点击工作台统计进入明细 | 日期、范围、客户和业务方式条件完整带入并回显 |

## 审批与敏感手机号

| 用例 | 操作 | 预期 |
|---|---|---|
| APPROVAL-001 | 查看“我的申请”并按条件筛选 | 仅本人申请；类型、状态、阶段、日期和关键词有效 |
| APPROVAL-002 | 经理审批本部门申请 | 只处理本部门授权类型，不能自审或读取跨部门数据 |
| SENSITIVE-001 | 员工额度内首次解锁客户手机号 | 不创建审批；按员工、客户、日期计一次并返回单次明文 |
| SENSITIVE-002 | 同日重复查看同一客户 | 不重复扣次；审计记录完整 |
| SENSITIVE-003 | 顾问超限、经理超限 | 顾问转经理审批；经理转老板审批；批准范围不扩大 |
| SENSITIVE-004 | 老板或超级管理员查看 | 直接返回单次明文并留审计；列表仍只返回脱敏值 |
| SENSITIVE-005 | 检查响应、日志、导出和数据库账号 | 不泄露 `phone_plain`、AES 密文、token 或密钥 |

## 报告与跨端联动

| 用例 | 操作 | 预期 |
|---|---|---|
| REPORT-001 | 客户生成并查看报告 | 只含经营分析、风险提示和优化建议，不含银行、准入、匹配或业务 ID |
| REPORT-002 | 员工查看聚合报告 | 按对象权限展示画像、经营分析、内部匹配和渠道参考 |
| REPORT-003 | 分类上传材料并触发 OCR/AI | 只接受白名单类别；状态真实；不虚构一致性核验 |
| CROSS-001 | 小程序提交资料后从 Web 查看 | 字段、归属和状态一致；客户侧字段不越界 |
| CROSS-002 | Web 创建预约后从 H5 / 小程序查看 | 时间、方式、状态与通知一致，重复请求不重复写入 |
| CROSS-003 | Web 审批外出或手机号申请 | 申请状态、通知铃铛、未读数和后续权限跨端一致 |

## 数据、安全与性能

1. 用 `EXPLAIN` 检查客户筛选、服务名单、通知未读和报告聚合，避免无条件全表扫描与 N+1。
2. 检查分页边界、深分页、特殊字符、SQL/JSON 注入、断网重试和并发提交。
3. 顾问跨客户、经理跨部门、渠道访问内部数据、伪造角色或归属字段均应被后端拒绝。
4. 网关拒绝响应只写一次；错误体统一包含 traceId，不泄露 SQL、堆栈或配置。
5. 每次回归重新记录实际测试结果，不把上一次执行状态写入本用例文档。
