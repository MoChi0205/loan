## #1 审批通过后，已审批数据从列表「消失」

**根因**：审批中心多个 tab 的后端接口**硬编码只返回待审（PENDING）**，审批通过/驳回后状态变了 → 从待审列表消失，且前端没有状态筛选入口，已审数据无处可看。

| tab | 接口 | 原行为 | 修复 |
|---|---|---|---|
| 手机号查看审批 | `SensitiveViewService.pendingApprovals` | 硬编码 `PENDING` | 加 `status` 参数 |
| 客户分配审核 | `ClientAllocationService.pendingPage` | 硬编码 `PENDING` | 加 `status` 参数（内存过滤） |
| 渠道线索审核 | `LeadService.channelPendingPage` | 硬编码 `PENDING_APPROVAL` | 加 `status` 参数 |
| 外出审核 | `OutingService.pending` | 硬编码 `PENDING_REVIEW` | 加 `status` 参数 |
| 短信/报告模板审核 | `ApprovalService.pendingSlice` | 硬编码 `STATUS_PENDING` | 加 `status` 参数贯穿 unifiedPending |
| 产品/下载审核 | — | 已有 status 参数 | 无需改 |

**前端**：所有缺状态的 tab 补「审批状态」下拉（待审/已通过/已驳回），后端默认仍走"待审"语义（保持原 UX），可选全部状态。

## #2 日志「业务异常: code=1002, 审批单不存在或已处理」批量出现

**根因**：**前端无防重**。`auditSensitive` 等单条审批接口没有 loading 保护，用户连点/列表未及时刷新导致同一审批单被并发提交；后端用 `eq(status=PENDING)` 条件更新（CAS），第一个请求成功，后续请求 `update 0 行` → 抛「审批单不存在或已处理」。

**修复**：`auditSensitive` 加 `sensitiveAuditing` 防重（请求进行中禁止重复提交）。后端 CAS 幂等保持不动（正确防线）。

> 这类"审批单不存在或已处理"不是数据丢失，是幂等保护的正常结果；但前端防重后用户不会再看到。
