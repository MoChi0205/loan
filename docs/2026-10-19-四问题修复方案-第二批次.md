## 新1：我的客户列表加「编辑档案」「发起初筛」快捷入口

**现状**：操作列宽 200，MY 视角只有「查看档案 / 快速跟进 / 释放回公海」；编辑档案弹窗（`openEdit`）与发起初筛入口（`goScreening` → `/screening`）都已存在，只是埋在详情页/顶部按钮里。

**方案**
1. 操作列新增两个快捷按钮：
   - 「编辑档案」：点击后先拉该客户详情（`getClientDetail(row.clientCode)`）再打开既有编辑弹窗，与详情页行为完全一致；
   - 「发起初筛」：跳转 `/screening` 并带 `query.clientCode` 预选该客户（初筛页若不支持预选则小改支持）。
2. 操作列宽 200 → 260，按钮过多时折叠为「更多」下拉，避免挤压。

## 新2：审批中心命名澄清 + 一键审批

**现状**：审批人视角被拆成 8 个路由 tab（客户分配审核/产品/外出/材料复核/手机号查看…），「我的申请」副标题是"查看本人发起的全部申请与当前审批进度"——两个视角区分度不足；全部表格均无多选列，后端也没有批量审批接口（现存的 batch 都是分配/认领，不是审批）。

**方案**
1. **命名澄清**：
   - 「我的申请」→「我发起的」，副标题改为「我提交给他人审批的单子与当前进度」；
   - 各审批人 tab 标题统一加「待我审批」语义（如「客户分配审核」副标题改「他人提交、等待我审批的单子」），顶部 tab 名保持不变。
2. **一键审批**（本批先做「客户分配审核」tab，其余 tab 需要时复用同一模式）：
   - 前端：表格加多选列 + 底部「批量通过 / 批量驳回」按钮，二次确认后逐条调用并汇总成功/失败；
   - 后端：`POST /api/admin/approval/allocation/batch-audit`（body: approvalNos + approve/reject + opinion），循环复用既有单条审批逻辑（含跨团队两级推进语义），返回逐条结果明细。

## 新3：客户认领/转移审批链路（对照结果：大部分已实现）

| 你的规则 | 现状 |
|---|---|
| 发起前按手机号/姓名手机号/企业编码查已有归属 | ❌ **未绑定流程**：查重接口已有（`GET /client/lookup`），但发起审批时没有强制先查 |
| 无归属 → 直接认领，免审批 | ✅ 已实现（公海认领即时生效） |
| 有归属 + 同团队 → 上级经理审批 | ✅ 已实现（TEAM_REVIEW 单级） |
| 有归属 + 跨团队 → 经理通过后老板终审 | ✅ 已实现（TEAM_REVIEW → BOSS_REVIEW 两级） |
| 审批通过后进入申请人名下 | ✅ 已实现 |
| 经理提交：本团队经理可直接分配 | ✅ 已实现（本团队即时落归属） |
| 经理提交：跨团队 → ？ | ⚠️ 你这句话没说完；现状是**直接拒绝**（"跨团队客户不可直接分配，需提交申请并由老板审批"） |

**方案**
1. **发起前查重绑定流程**：「客户认领/转移」发起弹窗改为两步式——
   - 第一步：输入手机号 / 姓名+手机号 / 企业编码 → 调既有 lookup 接口 → 展示匹配到的客户及其当前归属人/部门；
   - 第二步：系统自动分流——无归属显示「直接认领」按钮（免审批）；有归属显示「提交审批」按钮并自动带出原归属信息，弹窗上直接标注预计审批链路（同团队→经理 / 跨团队→经理+老板）。
2. **经理跨团队场景待你补全规则**（见待确认清单）。

## 新4：策略模板-添加步骤（中文文案 + 运算符可选）

**现状**（`StrategyTemplateList.vue`）：
- 已选条件直接渲染 `s.conditionField`（英文 field_code 如 `tax_grade`）；接口返回的 RuleDTO 里其实有中文 `fieldName`，前端没用；
- 运算符输入框是有意 disabled（"选择规则后自动带出（只读）"）；条件值在某些场景禁用（空值类运算符/布尔/黑名单）。

**方案**
1. **中文文案**：已选条件与步骤编辑弹窗中，`fieldCode → fieldName` 映射渲染（数据源即规则列表自带中文名），映射不到时回退英文码；
2. **运算符可选**：disabled 输入框改为下拉选择（等于/不等于/大于/大于等于/小于/小于等于/包含/属于/为空/不为空），默认带出规则原运算符、允许修改；条件值的既有禁用逻辑保留（为空/不为空、布尔、黑名单类）；
3. ⚠️ 需确认执行侧消费的是**步骤上的运算符**（`conditionOperator`）而非规则模板原值——若引擎读的是规则原 operator，需要同步改执行取值处（开发时核实并打通）。
