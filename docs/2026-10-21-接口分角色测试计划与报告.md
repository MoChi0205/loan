## 二、登录与鉴权机制（已打通）

- 登录：`POST /api/auth/password-login`（图片验证码 captchaId+captchaCode + RSA 加密密码 + accountType）。
  验证码答案存远程 Redis `loan:auth:captcha:<captchaId>`（5 分钟、一次性）。
- JWT：HS256，`jwt.secret` 经 SHA-256 派生签名密钥；claims = userId/userType/userNo/roleCode/clientType。
- 会话：Redis `loan:session:<TYPE>:<userId>`，登录写入，请求滑动续期。
- 网关统一鉴权（`ApiAuthGlobalFilter`）：白名单放行；无 token → 401 `code:2000`；未登记 → 403 `code:2001`；
  角色未授权 → 403；端不匹配 → 403。**服务 9080 内部 `JwtAuthenticationFilter` 同样校验**（直连业务接口也 401）。
- 已拿到 8 个 token（BOSS/ADVISER/ADVISER2/DEPT_MANAGER/OPERATOR/SUPER_ADMIN/SUPER/CHANNEL），密码统一 Test123456。

## 四、测试方法与断言标准

- 统一响应 `{code,message,data,traceUuid}`，`code=0` 成功；401 `code:2000`；403 `code:2001` 或业务 403。
- 每用例：请求（方法+路径+参数+角色 token）→ 期望（客观：HTTP 码/code/数据范围）→ 实际（真实输出原文）→ 结论。
- 数据范围用例：ADVISER 只能看到本人数据、DEPT_MANAGER 本部门、CHANNEL 仅本人、越权访问他人数据应拒绝。
- 越权用例：低权限角色请求高权限接口应 403；未授权端请求应 403。

### 缺陷 D1：`GET /api/channel/lead/page` 渠道访问返回 5000（环境不一致，非代码缺陷）

- 现象：CHANNEL 角色访问 `/api/channel/lead/page` 返回 `code=5000 系统异常`，而非渠道线索列表。
- 实际输出：`HTTP200 code=5000 data=None`。
- 根因（日志实证，`logs/error.log`）：`NoSuchMethodException: ChannelLeadController.leadPage(..., LocalDate, LocalDate, LoanUser)`；
  `LocalVariableTableParameterNameDiscoverer` 从磁盘新 `.class`（上一轮 Bug4 给 leadPage 加的 createdAtStart/End 参数）读参数名，
  但运行中进程仍加载旧代码（旧签名），签名不匹配抛异常。即**改了后端代码未重启服务**导致。
- 处理：重启后端加载新代码后复测，`/api/channel/lead/page` 恢复 `code=0 records=0`（渠道未录入线索，正常空列表）；BOSS/OPERATOR/SUPER 仍 `code=2001`、ADVISER/DM 仍 `HTTP403`，符合角色边界。
- 定性：环境不一致，非代码缺陷；不计入缺陷修复，但已记录供复测闭环。

## 七、阶段结论（2026-10-21 第一批）

- 已测 10 个接口域（认证/客户/线索/产品/审批/组织/敏感/渠道/报告/服务运营），**鉴权边界与对象数据范围全部符合预期，未发现越权或数据范围缺陷**。
- 唯一异常（`/api/channel/lead/page` 5000）经日志定位为「改后端代码未重启服务」导致的环境不一致，重启后恢复，非代码缺陷。
- 待续批次：小程序域（CUSTOMER 角色，需小程序登录 token）、黑名单/短信/通知/审计/OCR/导入/规则/计划/字典/附件/apiperm 等其余域。

### 环境问题复盘（重要，已记入今日 memory）

1. **改后端代码后必须重启服务**，否则磁盘 `.class`（新签名）与运行中 class（旧签名）不一致，
   首次请求该接口时 Spring `LocalVariableTableParameterNameDiscoverer` 抛 `NoSuchMethodException` → 5000。
2. **`service.sh` 的 `MVN` 依赖 `command -v mvn`**，本机 mvn 不在 PATH（在 `~/Documents/apache-maven-3.8.8/bin/mvn`），
   直接 `service.sh restart` 会因 `$MVN` 为空报 `line 104: command not found`，需 `LOAN_MVN=<绝对路径>` 覆盖。
3. **macOS 15 `launchctl bootstrap` 托管失效**（无标签、无日志、端口不起），`service.sh start` 只负责构建 JAR，
   需再用 `run_in_background` 直接拉起（参数照抄 service.sh）。重启 backend 时网关 9088 曾被连带误停，需一并恢复。
