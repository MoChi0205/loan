## 当前不合理之处

| 优先级 | 问题 | 影响 | 建议 |
|---|---|---|---|
| P0 | 菜单授权与接口授权仍有两套来源 | 配置页面与接口能力存在漂移风险 | 以角色×端×接口 allow-list 为唯一运行时判定，并由菜单矩阵生成授权 |
| P1 | 权限变更依赖缓存刷新 | 登录后短时间看到旧菜单 | 迁移完成后主动清理菜单和接口规则缓存 |
| P1 | Redis 远程链路仍有约 0.1～0.5 秒基础延迟 | 工作台多接口并发时放大首屏耗时 | 将只读缓存聚合并减少一次请求内的 Redis 往返次数 |
| P1 | 前端构建存在大 chunk 与 circular chunk 警告 | 首屏加载和缓存拆分有风险 | 按路由拆分报表、规则和组织管理模块，复查循环依赖 |
| P1 | 部分历史表仍使用自增主键做内部关联 | 迁移和跨系统追溯困难 | 新增关联统一使用业务编码，存量表按模块分批迁移 |
| P2 | OCR/AI、微信和短信仍按开发 Mock/占位配置 | 无法代表生产第三方链路 | 切换真实配置前单独做费用、授权和数据出境验收 |
| P2 | 启动脚本依赖 macOS GUI 后台域 | 无 GUI bootstrap 域时服务无法启动 | 已加普通后台进程回退；后续可改为跨平台进程管理器 |

## 当前 P0-P1 修复（2026-10-17 更新）

- 线索手机号查看统一复用客户“每日首次客户解锁”额度、数据范围和分级审批；历史永久授权不再绕过日额度。
- 顾问/运营超限由部门经理审批，部门经理超限由老板/超管审批；老板/超管无限查看但仍记录每日审计留痕。
- 敏感接口仅允许签名 JWT 中 `clientType=WEB`；小程序令牌不能通过伪造 `X-Client-Type` 绕过。
- 短信日志不再输出验证码和完整手机号；SQL 只记录 statement、操作与耗时，不记录 SQL 参数。
- 业务 Mapper 已清除 `@Select/@Update/@Insert/@Delete` 注解 SQL，统一使用 Wrapper 和批处理辅助组件。
- 页面未知枚举不再原样暴露英文编码，统一显示中文兜底。
- 名单/产品城市批次改为一次自然键预查，移除逐条前置计数；并发重复键通过 Wrapper 当前读确认，业务编码冲突不静默吞掉。
- 团队公海敏感查看范围与客户详情一致：顾问不可查看团队公海原值，经理仅允许本部门团队公海。
