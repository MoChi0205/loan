### 🔴 P0-5 · 工单日期筛选逻辑错误（"今日"筛不出今日）

| 项 | 内容 |
|---|---|
| **位置** | `renderOrder()` 第 972–975 行 |
| **现状** | ```js<br>if(state.orderFilter.date==='today' && o.age.indexOf('h')<0 && o.age.indexOf('m')<0) return false;```<br>`age` 字段值为 `'2h'`/`'18h'`/`'3d'`/`'9d'`。`'18h'` **同样包含 `h`** → 18 小时前的工单被判定为"今日" |

## 三、P1 重要缺陷（体验受损 / 设计系统不一致）

### 🟠 P1-1 · 设计 Token 形同虚设（定义了但零执行）

| 项 | 现状 |
|---|---|
| **字号 Token** | `--fs-xs/sm/md/lg/xl` 定义了 5 个变量 → **全文件引用次数 = 0**。实际全用裸值：11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 15 / 16 / 19 / 22 / 26px 共 **12 种字号** |
| **间距 Token** | **完全缺失**。全文件 padding / margin / gap 均为裸值（4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 20 / 24 / 42 / 48 / 70px），无 4px 基准体系 |
| **圆角 Token** | **完全缺失**。混用 6 / 8 / 9 / 10 / 12 / 13 / 14 / 16 / 24 / 44 / 56 / 999px 共 **12 种值** |
| **阴影 Token** | `--shadow-sm/md/lg` 定义了，但多处仍用裸值 `box-shadow:0 1px 3px rgba(11,29,58,.04)` |
| **过渡 Token** | **完全缺失**。`.15s` / `.18s` / `.2s` / `.28s` 混用无体系 |

**修复建议**：建立完整 Token 层并**全量替换**（见 §五 5.1），这是后续所有组件收敛的基础。

### 🟠 P1-4 · 键盘可访问性为零

| 项 | 现状 |
|---|---|
| `:focus-visible` | 全文件出现 **0 次** |
| 焦点样式 | 仅 `.form-input:focus` 与 `.form-textarea:focus` 有（金色边框） |
| 无焦点指示的元素 | 所有 `.btn` / `.tab` / `.card` / `.report-card` / `.date-chip` / `.seg-item` / `.mini-btn` / `[data-sub]` / `[data-back]` |

**修复建议**：① 全局补 `:focus-visible{outline:2px solid var(--gold);outline-offset:2px}`；② 所有可点击 `div` 补 `role="button"` + `tabindex="0"`；③ 状态标签补 `aria-label`（如"状态：待审批"）；④ tabBar 补 `role="tablist"` / `role="tab"` / `aria-selected`。

### 🟠 P1-8 · hover 态缺失（桌面端无反馈）

所有可点击元素（`.card` / `.report-card` / `.quick` / `.list-item` / `.tool-item` / `.tab`）**只有 `:active`（移动端按压），无 `:hover`**。原型在桌面浏览器演示时鼠标悬停无任何反馈，交互感缺失。

**修复建议**：补 `:hover` 态（卡片 `box-shadow` 提升 + `translateY(-1px)`，列表项背景 `#FAFBFC`），并用 `@media (hover:hover)` 包裹避免在触屏上产生粘滞 hover。

## 五、设计系统整改方案

### 5.1 Token 体系重建（优先级：最高）

现状问题：Token 定义了但未执行；间距/圆角/过渡三类完全缺失。

**建议补全的完整 Token 层**：

```css
:root{
  /* ===== 间距：4px 基准 ===== */
  --space-1:4px;  --space-2:8px;  --space-3:12px; --space-4:16px;
  --space-5:20px; --space-6:24px; --space-8:32px; --space-10:40px;
  --space-12:48px; --space-16:64px;
  /* 语义间距 */
  --space-card-pad:var(--space-4);      /* 卡片内边距 16px */
  --space-page-gutter:var(--space-4);   /* 页面左右留白 16px */
  --space-stack:var(--space-3);         /* 卡片间垂直间距 12px */

  /* ===== 圆角：4 级 ===== */
  --radius-sm:8px;    /* chip / tag */
  --radius-md:12px;   /* 卡片 / 输入框 / 按钮 */
  --radius-lg:16px;   /* 主卡片 */
  --radius-full:999px;/* 徽章 / 头像 */

  /* ===== 字号：6 级 ===== */
  --fs-xs:11px;   /* 辅助说明 / ID */
  --fs-sm:12px;   /* 次要信息 */
  --fs-md:13px;   /* 正文 */
  --fs-lg:15px;   /* 卡片标题 */
  --fs-xl:18px;   /* 页面标题 */
  --fs-2xl:22px;  /* KPI 数值 */

  /* ===== 过渡：3 级 ===== */
  --transition-fast:150ms ease;
  --transition-base:200ms ease;
  --transition-slow:280ms ease;

  /* ===== 无障碍色（对比度已验证 ≥4.5:1） ===== */
  --warning-text:#B45309;   /* 替代 #F59E0B 作文字色，实测 4.54:1 ✓ */
  --gold-text:#3A2E12;      /* 暖金底上的文字色，实测 ~7:1 ✓ */
}
```

**执行要求**：全量替换裸值，禁止新增裸 `padding` / `margin` / `font-size` / `border-radius` / `transition`。

### 5.2 组件收敛（从 12 变体 → 6 基础组件）

| 组件 | 收敛前 | 收敛后 |
|------|--------|--------|
| **Button** | 12 变体 | **3 层级 × 3 尺寸**：Primary（品牌深蓝，主操作）/ Secondary（描边，次操作）/ Tertiary（文字，弱操作）；尺寸 lg/md/sm |
| **Card** | 7 种圆角 | **1 基础 Card** + variant：`--default`（白底）/ `--flat`（无阴影）/ `--accent`（渐变头） |
| **ListItem** | 3 套 | **1 基础 ListItem** + slot（leading icon / title / desc / trailing） |
| **Badge** | 3 套 | **1 基础 Badge** + 语义色 variant（success / warning / danger / info / neutral） |
| **Empty** | 2 套 | **1 基础 Empty**（图标 / 标题 / 描述 / 操作按钮） |
| **Stepper** | 2 套 | **1 基础 Stepper**（支持横向 4 步 / 纵向 N 步两种 layout） |

**收敛收益**：CSS 体积预计减少 25–30%；后续改版只需改 1 处而非 3 处。

---

### 5.3 无障碍基线（必须满足）

| 项 | 标准 | 当前 | 目标 |
|---|------|------|------|
| 文字对比度 | ≥ 4.5:1（正文）/ 3:1（大字 ≥18.66px 或 ≥24px） | 4 处不达标 | **100% 达标** |
| 触控目标 | ≥ 44×44px | 3 类不达标 | **100% 达标** |
| 键盘可达 | 全部交互元素可 Tab 聚焦 | 0% | **100%** |
| 焦点可见 | `:focus-visible` 明确指示 | 仅输入框有 | **全部交互元素** |
| 语义标签 | `role` / `aria-*` | 缺失 | 补 `role="button"` / `tabindex="0"` / `aria-label` |
| 动效偏好 | 尊重 `prefers-reduced-motion` | 未处理 | 加媒体查询降级 |

---

### 5.4 交互状态矩阵（补全缺失态）

每个可交互元素必须定义 **6 态**，当前普遍只有 2 态（默认 + active）：

| 状态 | 当前覆盖 | 需补全的元素 |
|------|---------|-------------|
| Default（默认） | ✅ | — |
| Hover（悬停） | ❌ | 所有可点击元素（P1-8） |
| Active（按压） | ✅ | — |
| Focus（键盘焦点） | ❌ | 所有可点击元素（P1-4） |
| Disabled（禁用） | ⚠️ 仅 `.btn:disabled` | 输入框 / chip / seg-item 需补 |
| Loading（加载中） | ❌ | 提交审核 / 发起匹配 / 查重 / 查询（P1-5） |

## 七、结论

当前原型**视觉风格已建立**（深海军蓝 × 暖金、暗画布 + 亮屏），**信息架构与步骤化交互经两轮迭代已明显改善**，但存在**两类结构性问题**：

1. **业务闭环断裂**——7 项 P0 中，有 5 项是"UI 做了但流程走不通"（C4 零落地、删除审批无审批方、筛选无过滤、查重无绑定、分配后不前进）。这类问题在真实演示中会**直接暴露**，建议优先修复。

2. **设计系统未成体系**——Token 定义了零执行、组件多套并行、无障碍全面缺失。这类问题**不影响演示但影响工程化交付**，建议在原型冻结后、进入 uni-app 编码前完成收敛，否则每个 Token 裸值都会成为后续技术债。

**建议下一步**：先确认 P0 的 5 项流程断裂是否按上述方案修复，再由我输出**收敛后的设计系统规范文档**（含完整 Token 表 + 6 个基础组件的规格与代码），作为 uni-app 编码的直接依据。
