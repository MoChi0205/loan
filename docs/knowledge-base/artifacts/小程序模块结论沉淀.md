## 模块一 · 角色权限模型（智能匹配操作资格）

### C1 结论：谁可以「操作智能匹配」

| 角色 | userType | 能否操作智能匹配 | 说明 |
|------|----------|------------------|------|
| 客户 | CUSTOMER | ✅ | 仅对自身已认证企业发起匹配 |
| 渠道合作方 | CHANNEL | ❌ | **不可**操作智能匹配；渠道定位为「产品供给方 + 客户线索录入方」，tab 仍为「我的产品 / 录入客户」，**不显示智能匹配** |
| 顾问 | STAFF | ✅ | 替客户 / 对归属企业发起 |
| 部门经理 | STAFF | ✅ | 同顾问 + 团队归属企业 |
| 老板 | STAFF | ✅ | 同顾问 + 全量归属企业 |
| 运营管理员 | STAFF | ✅ | 有资格；小程序侧承载仍轻，主体在 Web |
| 超级管理员 | STAFF | ✅ | 有资格；同运营 |

**关键澄清**：此前 V3.0 多处将「智能匹配」写成「仅客户可用」。现修正为——**客户（自身）+ 全部企业员工（STAFF，渠道除外）均可操作**；渠道合作方是唯一的「不可操作匹配」角色。

**影响文档**：整体功能方案 §一、实施规格 V3.0 §二/§五、交互方案 §1.2、交互原型 `renderMatch` 守卫逻辑。

## 模块二 · 智能匹配（顾问/员工替客户匹配 + 客户归属流转）

### C2 结论：替客户发起匹配的前置——客户归属流转

员工（顾问/经理/老板/运营/超管）替客户操作匹配前，先判断目标企业在系统中是否存在数据：

- **情形 A · 系统中无该企业用户数据**
  1. 先录入该企业 / 个人客户的基础数据（即录一条客户档案 / 线索：`企业名 / 联系人 / 手机号 / 客群` 等）。
  2. 系统**自动新增该客户并将其归属（owner）分配给当前用户**。
  3. 再填写该企业的「**企业经营事实**」（纳税/开票/成立年限/行业等）。
  4. 上传**经营材料**（经营数据 / 企业年报 / 附件 / 照片）。
  5. 点击「开始匹配」。

- **情形 B · 系统中已存在该企业数据，但不在当前用户名下**
  1. 发起「**申请分配给当前用户**」。
  2. 归属流转规则（**已确认**）：
     - **老客户已有归属人**（归属到某员工）→ 申请 **自动归属** 流转给当前用户，**无需审批**。
     - **老客户无归宿**（公海 / 无 `owner` 记录）→ 申请需走 **上级 / 运营审批**，审批通过后归属流转给当前用户。
  3. 获得归属后，方可对该企业发起匹配。

**归属字段**：客户档案归属 `owner_staff_code`；线索 `t_lead.owner_staff_id` / `recorder_staff_id`。
**本质规则**：匹配只能在「**我归属的客户**」上发起；新客户走「录入即分配」，老客户走「申请分配 → 自动归属（无归宿才需审批）」。

**影响文档**：整体功能方案（新增章节）、实施规格 V3.0 §四（智能匹配页规格）、交互方案（新增章节）、交互原型（顾问/员工 match 页 stepper + 录入基础数据入口）。

## 模块三 · 我的报告（查询权限与维度）

### C3 结论（2026-08-29 重大修正）：按角色二分查询权限

> **本次推翻**：之前 C3 写的"客户可按手机号/企业名/归属跨归属检索"是错的，本质混淆了"客户查自己"与"员工查全量"。现按角色严格二分。

| 角色 | 可查范围 | 可用维度 | 备注 |
|------|----------|----------|------|
| **客户 CUSTOMER** | **仅自己**的报告 | **仅按日期**筛选 | **无手机号搜索、无企业名搜索、无归属筛选**；客户的查询维度是"日期 chip（今日/7 天/30 天/全部）"，最简能力 |
| **企业员工**（顾问/经理/老板/运营/超管） | **全部**报告（不限归属、不限客户） | 手机号 / 企业名称 / 归属（到我/员工/全量） / 日期 | 用于陪访、跨归属穿透；顾问、运营、超管"全量"为默认选中 |
| **渠道 CHANNEL** | 不可见 | — | 沙箱隔离，不展示「我的报告」入口（继承 C1） |

**原则**：
- **客户**只关心"自己哪一天生成了报告"——简单日期筛。
- **企业员工**承担"全量检索 + 陪访解读"职责——多维组合筛。
- 任何"我查别人报告"的能力**绝不放给客户**，避免越权查看他人经营数据。

**影响文档**：实施规格 V3.0（报告页规格·角色分支）、交互方案（报告查询交互·角色分支）、交互原型（`renderReport` 按角色返回不同筛选面板 + 不同标题/视角）。

## 模块四 · 银行产品可见性（匹配结果读取）

### C4 结论：谁能查看「匹配的银行产品」

- **顾问（ADVISER）**：默认可看**全部**企业匹配命中银行产品（**已确认：顾问可看全部，不限本人归属**）。

## 模块九 · 渠道产品删除 / 撤销审批（C9）

### C9 结论：渠道对自有产品的撤销 + 删除审批流
