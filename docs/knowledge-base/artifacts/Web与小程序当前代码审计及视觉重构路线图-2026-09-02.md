## 1. 结论摘要

当前主链路四阶段代码整改已完成。原审计确认的 **55 项问题**（Web 28 项、小程序 27 项）均已完成代码修复；自动化测试与构建通过，现有 Web 环境已完成登录及工作台烟测。涉及真实数据规模、弱网、全角色与微信真机的项目保留为“已修复待专项回归”，不将未执行的人工验收写成已完成。

本轮完成重点集中在四类：

1. **业务正确性**：小程序材料核验仍有硬编码失败结果、工单状态枚举与后端不一致、替客上传可能绑错客户、顾问新建客户文案与 D39 归属规则不一致。
2. **权限安全**：Web 动态菜单失败仍采用 fail-open；过滤结果异常时回退全集。
3. **可规模化交互**：Web 多个下拉一次只取前 100/200 条，数据增长后会“搜索不到”；审批中心首屏并发加载三个页签。
4. **设计一致性**：姓名主显尚未全覆盖；Web 仍大量内联 SVG，小程序 `AppButton` 契约与调用方不一致。

状态说明：下方保留原审计表现和根因作为追溯证据；状态已统一更新为“已修复待回归”。自动化已覆盖编译、测试和构建；真实数据规模、全角色、弱网和微信真机仍按第 8 节验收矩阵执行。

## 5. 视觉重构方案

### 5.1 统一设计原则

- **业务先于装饰**：一个页面只突出一个主任务；内部编码、trace、主键不占视觉主位。
- **名称主显**：人员显示姓名+部门/角色，客户显示姓名/企业名，产品显示产品名+机构；编码仅在详情“审计信息”提供复制。
- **状态语义唯一**：成功/处理中/警告/失败分别映射统一 Token；后端不得下发颜色值。
- **跨端同源、密度有别**：Web 使用信息密集表格与侧栏；小程序使用任务卡片、分步表单和底部导航，但共享颜色、圆角、状态和图标语义。
- **角色化视图模型**：组件可复用，标题、入口、字段和动作由角色配置生成，不在模板堆叠散落判断。

### 5.2 Web 信息架构

1. 顶层保持“工作台—客户经营—匹配规则—服务审批—产品渠道—数据报表—系统管理”。
2. 列表页统一为：页头/主操作 → 搜索条件 → 错误或空态 → 表格 → 分页；禁止把请求失败伪装为空数据。
3. 详情页统一为：对象名称与状态 → 关键业务信息 → 关联流程 → 审计信息；编码放最后。
4. 审批中心改为按页签懒加载；待办数量在页签标题显示，审批弹窗明确对象名称、原状态、目标状态。
5. 所有人员、客户、产品选择统一使用远程分页组件，支持取消旧请求、300ms 防抖和批量回显。

### 5.3 小程序信息架构

1. 首页只承载欢迎、认证状态、两项高频入口和合规提示；不恢复手动邀请码，也不放顾问服务卡。
2. 【我的】承载账户、服务顾问、服务单、分享邀请、奖励和角色管理入口；引荐人与服务顾问分栏展示。
3. 智能匹配按“目标客户—经营事实—材料—核验—结果”推进，每步真实校验，不展示伪核验结论。
4. 员工替客场景使用统一 `activeClientCode` 上下文贯穿查重、认领、上传、匹配和报告。
5. 所有页面使用统一 PageShell 预留自绘 TabBar 与安全区；列表使用 Skeleton/Error/Empty/LoadMore 四态组件。

### 5.4 Token 建议

| 类别 | 统一规则 |
|---|---|
| 品牌主色 | 深海军蓝用于主操作和选中态；暖金只用于高价值强调，禁止大面积铺底 |
| 背景层级 | 页面背景、卡片背景、输入背景三层固定；暗色模式使用同一语义变量 |
| 圆角 | 卡片/弹窗/按钮/标签四档，页面禁止自行创造新半径 |
| 间距 | 4/8/12/16/24/32 基准；小程序换算 rpx 但语义名称一致 |
| 字体 | 标题、正文、辅助、数字四级；编码只使用 mono 辅助样式 |
| 状态 | success/warning/danger/info/muted 五类；颜色与文本同时表达，不只靠颜色 |
| 动效 | 120–200ms；尊重 reduced-motion；提交操作始终有 loading 和防重复点击 |

## 6. 图标统一方案

### 6.1 单一图标契约

Web 与小程序统一使用“**图标名称 + size + tone**”接口。业务数据和页面不得保存 SVG HTML 字符串，不使用 emoji 充当正式图标，不允许后端返回图标路径或颜色。

建议最小 registry：

| 语义组 | icon name |
|---|---|
| 导航 | `home` `workbench` `client` `match` `report` `order` `product` `approval` `mine` |
| 操作 | `add` `edit` `delete` `search` `filter` `refresh` `upload` `download` `share` `copy` |
| 状态 | `success` `warning` `error` `info` `pending` `empty` |
| 对象 | `enterprise` `person` `adviser` `department` `bank` `document` `attachment` |
| 方向 | `arrow-left` `arrow-right` `chevron-down` `expand` `collapse` |

### 6.2 落地规则

- Web：扩展 `loan-web/src/components/AppIcon.vue` registry；业务页只传 name。图表本体、品牌 Logo、完整空态插画可保留独立 SVG 组件。
- 小程序：保留 `loan-mini/components/AppIcon.vue` 零依赖方案，但由当前大量 `v-if` 逐步收敛为配置/子组件，补企业、个人、审批等缺口。
- 尺寸：`xs/sm/md/lg/xl` 五档；页面不得直接写任意宽高。导航、按钮、表格操作分别固定档位。
- 颜色：默认 `currentColor`；只接受语义 tone，不在页面传任意 hex。
- 可访问性：装饰图标隐藏；独立图标按钮必须有可读 label；图标不能作为唯一状态信息。
- 门禁：新增内联业务 `<svg>`、`v-html` 图标字符串或 emoji 图标应在代码审查中阻断。

## 8. 验收矩阵

- **角色**：客户、渠道、顾问、部门经理、老板、运营、超管。
- **客户归属**：本人认领幂等；他人归属必须转移审批；管理员直接分配立即生效；DM 只审本团队；并发申请不覆盖新归属。
- **邀请**：分享链接/二维码自动带码；有效期内首次绑定；过期、无效、自邀、重复消费均不改变归属。
- **名称主显**：抽查客户、工单、审批、初筛、计划配置，不以编码作为唯一可见信息。
- **规模**：构造 500+ 人员/产品/策略，远程选择和批量回显完整、无 N+1。
- **弱网**：菜单、查重、分页、上传、审批分别模拟超时/失败，页面必须有错误态和重试，不能永久 loading。
- **视觉**：iPhone 安全区、常见 Android、H5 375/768、Web 1280/1440；明暗主题；键盘与 reduced-motion。
- **工程**：相关单测、构建、lint/格式检查通过；新增结论回写 D 台账，修复项从“仍存在”转“已修复待回归”。
