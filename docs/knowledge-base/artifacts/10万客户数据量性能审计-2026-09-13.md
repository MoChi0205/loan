# 10 万客户数据量性能审计（2026-09-13）

## 已具备
- 客户、报告、审批、附件等主要列表已出现 MyBatis-Plus 分页接口。
- `BusinessNameService` 已提供名称批量装配和缓存，避免逐行查名称。
- Web 已有 `AppIcon`、按需 ECharts 组件，具备图标和图表统一入口。
- 接口访问日志已记录完整请求耗时和 `X-Query-Time-Ms`。

## 高风险项
1. `PlanLoaderService`、`PlanOrchestrationService`、`ProductStrategyService` 等仍有多个 `selectList()`；当规则、产品关联扩张时可能全量加载。
2. `ReportService`、`ApprovalService` 存在先查编码列表再二次查询的链路，需要确认每次都有限制并避免超大 `IN`。
3. `ApiPermissionSyncService` 以 `selectList(null)` 加载权限全表，启动同步可接受，但不应放在请求线程。
4. Dashboard/Report 统计需要确认是否全部使用 SQL 聚合；禁止把客户明细拉到 Java 后统计。
5. 计划、规则、产品详情虽有局部缓存，但需要统一 TTL、失效策略和缓存击穿保护。
6. 深分页应避免高 offset；客户明细超过百万后需增加业务编码/更新时间游标分页。
7. 关键索引需核对：客户归属、团队、状态、更新时间；审批状态+类型；报告客户+有效期；附件报告号/客户编码。

## 优先改造顺序
- P0：统计接口 SQL 聚合与角色数据范围；客户/报告/审批列表分页上限。
- P1：重复名称批量装配、详情缓存、统计缓存和写入失效。
- P1：补齐组合索引并用 EXPLAIN 验证；慢 SQL 阈值 500ms。
- P2：游标分页、读写分离和大批量导出异步任务。
