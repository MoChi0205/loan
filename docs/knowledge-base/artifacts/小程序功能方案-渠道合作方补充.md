## 二、渠道合作方能力地图

### 2.1 我的产品（查看自己录入的银行产品）

- **入口**：渠道工作台 / 「我的产品」卡片 → 列表页 `pages/channel/product-list`。
- **数据源**：`t_bank_product` 按 `channel_user_id = 当前渠道账号ID` + `source = CHANNEL_SELF` 过滤。
- **列表字段**：产品名称（内部名，仅渠道/管理端可见）、客群（企业/个人）、额度区间、利率区间、状态标签、更新时间。
- **状态标签**：`DRAFT` 草稿（灰）/ `PENDING` 待审核（橙）/ `APPROVED` 已入全量库（绿）/ `REJECTED` 已驳回（红）。
- **详情**：展示结构化「进件要求」（biz_terms_json）+ 审核工单状态与审核意见。

### 2.2 录入产品 + 进件要求（核心新增）

- **入口**：`pages/channel/product-edit`（新增）/ 列表点击进入编辑（草稿态可改）。
- **录入内容**：
  - 基础：产品名称、客群（企业/个人，个人产品不可挂企业规则 — 库表已约束）、额度区间、利率区间、期限区间、纳税门槛、开票要求。
  - **进件要求**：结构化表单（`biz_terms_json`）——即「渠道只填结构化表单，规则引擎由我司翻译」（数据库注释明确）。表单模板由后端下发（字典/配置），前端按 schema 渲染。
- **后端解析**：
  1. 渠道提交结构化表单 → 后端做字段校验 + 结构化解析（写入 `biz_terms_json`）。
  2. 若解析失败 → 返回明确错误（缺失必填/格式错误），前端红框提示，不进入审批。
  3. 解析成功 → 落 `t_bank_product`（`status=DRAFT`，`source=CHANNEL_SELF`，`channel_user_id=当前`，`bank_channel_id=当前账号所属渠道`）。
- **提交审批**：草稿 → 「提交审核」→ 生成 `t_product_approval`（`apply_type=CREATE`，`approve_status=PENDING`，`channel_user_id`，`before_snapshot_json` 空）→ `t_bank_product.status=PENDING`。

### 2.3 审批流（我司侧，渠道只读）

```
渠道录入(DRAFT) → 提交审核(PENDING) → 我司 DEPT_MANAGER/BOSS 审核(走 t_dept_approver 配置, 默认 BOSS)
        ↓ APPROVED                 ↓ REJECTED
   入全量库(APPROVED)            驳回(DRAFT/REJECTED, 需改后重提)
        ↓ 我司运营/渠道配置合作有效期
   创建 t_partner_product(ACTIVE) → 正式上架(对客可见)
```

- 渠道**只查看**进度：列表/详情展示 `approve_status` + `approve_opinion`（驳回意见必填可见）。
- 上架动作（`t_partner_product`）由我司侧发起（运营在 web 端或渠道在通过后再填合作有效期），渠道不可单方面上架。

### 2.4 录入客户信息（线索）

- **入口**：渠道工作台「录入客户」→ `pages/channel/lead-add`。
- **落表**：`t_lead`（企业 `t_lead_ent_ext` / 个人 `t_lead_person_ext`），`source = CHANNEL`，`recorder_staff_id = NULL`（渠道录入不归属直接进公海，库表注释明确：`渠道VIP录入不归属直接进公海`）。
- **字段**：联系人、手机号、客群，企业填公司名/信用代码/行业/纳税等；个人填姓名/城市/资产等（沿用既有 lead ext 字段）。
- **合规**：手机号 AES 入库 + SHA256 哈希查重（与现有逻辑一致）。

### 2.5 我司员工也能录入线索

- ADVISER / DEPT_MANAGER / BOSS 工作台新增「录入线索」入口（`source=BOSS/ADVISER`，`recorder_staff_id = 当前员工`，归属=录入人）。
- 复用同一 `t_lead`，仅 `source` 与归属字段差异；前端按角色展示「我的线索 / 公海」即可（线索后台能力已存在，前端补齐入口与表单）。
