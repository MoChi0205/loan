**录入与审批规则（已确认）**：
- 除「客户」外，**所有公司角色（渠道/顾问/部门经理/老板）均可录入银行产品与客户线索**。
- 所有银行产品提交后，**一律进入审批流，最终由运营管理员或超级管理员审批**（`t_product_approval.approver_staff_code` 落这两类角色）。
- 渠道账号按 `bank_channel_code` 做数据沙箱隔离——只能看自己录入的产品与审核进度，看不到其他渠道、也看不到客户匹配结果（库表注释已明确）。
- 运营管理员 / 超级管理员主要对应 Web 管理端，与既有「审批中心 / 报表中心 / 短信中心」衔接；小程序侧仅体现「审批结果回写」与「提交入口」。

**智能匹配操作资格（已确认，修正 V3.0「仅客户可用」表述）**：
- **客户**：仅对自身已认证企业发起匹配。
- **企业员工（STAFF，渠道除外）**：顾问 / 部门经理 / 老板 / 运营管理员 / 超级管理员均可操作智能匹配（替客户或针对归属所得企业数据发起）。
- **渠道合作方**：**唯一不可操作智能匹配的 role**，定位为「产品供给方 + 客户线索录入方」，tab 仍为「我的产品 / 录入客户」，不显示智能匹配。
- **查看匹配银行产品（读取权限，区别于录入权限）**：仅企业员工（渠道除外）可查看某企业的匹配命中银行产品；渠道受沙箱隔离仍不可见。

## 二、端到端流程（渠道产品上架）

```
任意公司角色（渠道/顾问/部门经理/老板）录入产品草稿
  └─ 填写进件要求（结构化表单）→ 后端解析校验（biz_terms_json 合法 JSON、额度/期限上下限、客群）
       └─ 提交审核 → 生成 t_product_approval(status=PENDING)
            └─ 运营管理员 / 超级管理员 审批（Web 审批中心，可填 reject_reason）
                 ├─ 驳回 REJECTED（带驳回原因，可重新编辑提交）
                 └─ 通过 APPROVED → 配置合作有效期（默认 1 年，录入方填 + 我司确认）→ t_partner_product 上架（status=有效）
```

- 草稿态（DRAFT）：渠道可编辑，未提交前不进入审批流。
- 待审态（PENDING）：只读，等待我司审核。
- 上架态：进入合作库，客户端「智能匹配」可命中。

## 四、数据模型（已核对，以迁移脚本为准）

- `t_channel_user`：渠道账号（`loan_user_id` 关联、`bank_channel_code`）。

## 五、合规红线（必须前置，不可绕过）

1. **授权与告知（PIPL）**。登录强制勾选隐私协议（V2 已规划）；OCR/AI 抓取证件必须单独明示授权；客户报告模板固定声明「数据来源合法、企业已授权、未经授权保留起诉权」。
2. **数据最小与隔离**。渠道沙箱隔离；AES 加密存储证件/手机号等敏感字段（写入用 typeHandler，读取在 Service 手动解密）。
3. **金融营销合规**。利率/费用明示、不得虚假宣传；涨跌颜色按中国惯例（涨红跌绿）、金额用 ¥。
4. **上架审核**。违规/不合规产品必须经我司审批后才可上架，杜绝渠道私自发布。
5. **短信合规**。营销群发含退订机制；验证码短信频次限制。
6. **审计留痕**。`@OpLog` 覆盖录入/提交/审批/导出/删除；无可逆动作先备份后执行。

## 七、登录 / 注册 / 邀请准入流程（新增）

**准入闸门**：进入小程序按角色免审/审核；但**所有客户在「去认证」后必须走 AI 审批 + 人工核验**。

| 进入方式 | 角色判定 | 进入小程序 | 认证 / 核验 |
|----------|----------|-----------|------------|
| 自然流量（无邀请） | 默认「客户」 | 直接进 → 客户页 | 认证 → AI 审批 → 人工核验 → 通知审批人 |
| 客户分享邀请 | 固定「客户」 | 直接进 → 客户页 | 同上 |
| 员工 / 渠道分享邀请 | 内部员工 / 合作渠道 | 待审核（命中内部 web 账号免） | 按角色另行核验 |
| 内部 web 账号匹配 wx_id/手机号 | 员工/渠道/运营/超管 | 直接进 → 对应角色页 | 免（已绑定可信身份） |
| 其他未匹配新用户 | 待定 | 待审核 | Web 审核通过后准入 |

**认证核验流程（所有客户）**：
1. 客户在小程序「去认证」提交资料（企业证照/OCR 抽取）。
2. **AI 审批**：规则引擎 + Qwen-VL 抽取做初筛与结构化（沿用 mds v2 混合模型，结果态 PASS/FAIL/SKIP…）。
3. **人工核验**：AI 初筛后转运营管理员 / 超级管理员（或指派审批人）做人工复核。
4. **通知**：核验环节通过站内信 / 短信通知对应审批人员；核验通过客户认证生效。
5. 核验未过：回退并提示补充材料，可重新提交。

- **邀请码 / 二维码角色预设**：分享时由分享方选定受邀角色，受邀者注册即带该角色——
  - 公司员工分享：可选「内部员工 / 合作渠道 / 客户」。
  - 渠道合作方分享二维码：可选「合作渠道 / 客户」。
  - 客户分享：固定「客户」。
- **内部账号绑定**：`t_staff` / `t_channel_user` 需维护 `wx_id` 与手机号；小程序登录时按 `wx_id` 或手机号回溯匹配，命中即免审核直接进入对应角色页。
- **待审核态**：审批前不可进入业务页面，仅展示「审核中」占位页；审批通过后按角色路由。

## 八、智能匹配操作权限与顾问代客匹配流

**操作资格**（见 §一 角色模型）：客户（自身）+ 全部企业员工（STAFF，渠道除外）。渠道合作方不可操作匹配。

**顾问 / 员工「替客户操作智能匹配」+ 客户归属流转**（C2）：
发起匹配前先判断目标企业在系统中是否存在数据：

- **情形 A · 系统中无该企业用户数据**
  1. 先录入该企业 / 个人客户的基础数据（客户档案 / 线索：企业名 / 联系人 / 手机号 / 客群）。
  2. 系统**自动新增该客户并将其归属（owner）分配给当前用户**。
  3. 再填写该企业的「企业经营事实」（纳税 / 开票 / 成立年限 / 行业等）。
  4. 上传**经营材料**（经营数据 / 企业年报 / 附件 / 照片）。
  5. 点击「开始匹配」。
- **情形 B · 系统中已存在该企业数据，但不在当前用户名下**
  1. 发起「**申请分配给当前用户**」。
  2. 归属流转规则（**已确认**）：
     - **老客户已有归属人**（归属到某员工）→ 申请 **自动归属** 流转给当前用户，**无需审批**。
     - **老客户无归宿**（公海 / 无 `owner` 记录）→ 申请需走 **上级 / 运营审批**，审批通过后归属流转给当前用户。
  3. 获得归属后，方可对该企业发起匹配。

**归属字段**：客户档案 `owner_staff_code`；线索 `t_lead.owner_staff_id` / `recorder_staff_id`。
**本质规则**：匹配只能在「**我归属的客户**」上发起；新客户走「录入即分配」，老客户走「申请分配」。

## 九、我的报告查询与经营诊断

**报告查询（C3 · 2026-08-29 重大修正）**：按角色严格二分——

| 角色 | 可查范围 | 可用维度 |
|------|----------|----------|
| **客户** | **仅自己**的报告 | **仅按日期**筛选（今日/7 天/30 天/全部），**无手机号搜索、无企业名搜索、无归属筛选** |
| **企业员工**（顾问/经理/老板/运营/超管） | **全部**报告（不限归属、不限客户） | 手机号 / 企业名称 / 归属（到我/员工/全量） / 日期，四维组合 |
| **渠道** | 不可见 | 「我的报告」tab 隐藏（沙箱隔离） |

**原则**：客户只关心"自己哪天生成的报告"——简单日期筛；企业员工承担"全量检索+陪访"职责——多维组合筛。**任何"我查别人报告"的能力绝不放给客户**，避免越权查看他人经营数据。

**匹配银行产品可见性（C4）**：企业员工（STAFF，渠道除外）可查看某企业的「匹配命中银行产品」列表；**顾问（ADVISER）已确认可看全部企业匹配产品（不限本人归属）**，部门经理 / 老板 / 运营 / 超管为全量；渠道合作方受沙箱隔离仍不可见客户匹配结果（含命中产品）。区分「录入产品（写入）」与「查看匹配产品（读取）」。

**经营诊断报告（C5，新增模块）**：在匹配报告之上，依据企业上传的经营材料产出——
1. **经营建议**：营收 / 成本 / 现金流 / 负债结构等可执行建议；
2. **风险提示**：税务异常 / 流水波动 / 负债率 / 行业风险等预警；
3. **企业历年营业数据**：按年汇总的营收 / 纳税 / 开票 / 利润等时序；
4. **多维数据统计**：行业对比、成长性、稳定性、合规性等维度图表。
- **数据源（已确认）**：优先**复用匹配时上传的经营材料**生成；**若材料不是最新，提示用户上传最新材料**后重新生成。
- **形态（已确认）**：以**独立详情页**呈现（点击报告卡进入），含上述四块 + 材料时效提示与「上传最新材料」入口。
定位为经营洞察层，可作顾问陪访物料，也作客户 self-service 报告之一。

**经营诊断详情页视觉重构（C6）**：排版专业 UI 化——
- 顶部页头：报告 ID + 生成时间 + 「上传最新材料」CTA。
- 核心指标卡：3-4 列 KPI（综合健康分 / 风险等级 / 同比变化 / 行业百分位）。
- 经营建议卡：每条带「建议类型」标签（优化/扩张/收缩/警示）。
- 风险提示卡：按高/中/低风险分区，仅展示存在项。
- 历年数据表：横向表（年份 × 指标）+ sparkline 趋势线。
- 多维统计：横向进度条 + 行业均值对比。
- 底部免责声明 + 重新生成时间。
- **返回按钮 + 子页标题排版修复**（避免「返回」「经营诊断」中文竖排）。

**服务单 / 工单筛选（C7）**：服务单 + 我的工单均支持四维筛选（客户姓名 / 手机号 / 时间范围 / 工单状态），工单卡显示工单 ID / 客户名 / 服务类型 / 状态 chip / 归属人 / 创建时间 / 跟进时长。

**我的页账户字段（C8）**：去客户编号，改显示实名状态 / 绑定手机号 / 性别 / 注册时间 / 邀请人。员工显示工号 / 部门 / 角色 / 入职时间；渠道显示所属银行 / 合作开始时间 / 联系人 / 银行编码。

**渠道产品删除 / 撤销审批（C9）**：
- 撤销审批：待审批状态可撤销，回到 DRAFT 草稿。
- 申请删除：已上架（OK）状态可申请删除 → 走我司运营/超管终审 → 审批通过从全量库物理删除。
- 撤销删除：待删除（PENDING_DELETE）状态可撤回。
- 通知：渠道发起 → 通知运营/超管；审批结果 → 通知渠道申请人。

**录入新客户自动查重分流（C10）**：替客匹配步骤 0 改为自动查重——输入企业名/手机号时系统查重，命中则跳"申请分配老客户"（带自动归属/审批规则提示），未命中则继续录入新客户表单。**去掉手动分段控件**。

**报告查询新增维度（C11）**：员工视图新增**客户姓名**、**统一社会信用代码**两个查询维度，4 维组合（手机号 / 客户姓名 / 统一社会信用代码 / 日期）+ 归属 chip。客户视图不受影响（仅按日期筛自己的报告）。

**全局排版修复（C12）**：roleBadge 徽章中文竖排 / .subbar 标题竖排 / 「上传补充材料」按钮不铺满 / 返回按钮竖排 等 3 类共性 UI 问题修复。**C12 是质量基线**——后续所有新增子页 / 弹窗 / 列表卡必须遵守这套排版规范。
