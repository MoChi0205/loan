# 客户公海、团队客户与分配回收规则（2026-09-08）

参考 `/Users/admin/Documents/crm/tse/docs2` 的成熟客户资源池逻辑，并以本项目已确认的七角色权限为最终口径。

## 视图与范围

- 全部公司员工：可查询公司全部客户基础信息、是否已建档、当前归属顾问姓名；查询不等于可操作。
- 顾问“我的客户”：仅本人归属客户。
- 部门经理“我的客户”：仅本人归属客户；部门经理可以成为客户归属人。
- 部门经理“团队客户”：本人部门全部顾问及本人名下客户，与“我的客户”独立展示。
- 公司公海 `ENTERPRISE`：全公司未分配客户，顾问可直接认领。
- 团队公海 `TEAM`：只允许所属部门员工认领或由该部门经理分配。

## 分配与审批

- 公司公海/本团队公海认领：直接原子落归属，不审批；并发仅一人成功。
- 所有公司员工角色均支持批量认领可见公海客户到本人；公司公海全员可认领，团队公海仅本团队成员可认领。单批最多 500，任一失败整批回滚。
- 已归属本人：幂等成功。
- 已归属他人：发起转分配申请。
- 同团队转分配：部门经理可直接分配或审批。
- 跨团队转分配：仅老板或超级管理员可审批；部门经理、运营不得代审。
- 部门经理只能直接分配至本部门顾问或本人，且不得直接覆盖其他团队客户。
- 老板、运营、超级管理员均可成为客户归属人，并可邀请客户、新增产品和新增线索。
- 新增线索、新增客户前必须按手机号等稳定字段检查公司全库；已存在时禁止重复新增，并返回可申请认领的内部关联信息。
- 企业硬查重键：手机号、统一社会信用代码；个人硬查重键：手机号、身份证号。任一命中即禁止新增。
- 企业名称或客户姓名相同仅返回同名提醒，不阻止新增；姓名不得单独作为唯一标识。
- 已存在客户/线索可申请认领：公司公海或本人团队公海直接认领，已有他人归属走转分配审批。

## 回收

- 顾问释放本人客户：进入公司公海，按全局配置设置冷却。
- 部门经理回收本团队顾问客户：进入本团队公海，按全局配置设置冷却。
- 部门经理不得回收其他团队客户。
- 部门经理支持本团队客户批量回收和批量分配，单批最多 500；复用单条范围校验并整批事务回滚。
- 自动超期回收：进入公司公海，并保留归属流转历史。

## 数据模型

`t_client_profile`：

- `owner_staff_code`：当前归属人；为空表示未分配。
- `sea_level`：`ENTERPRISE/TEAM`；已分配时为空。
- `sea_dept_code`：团队公海所属部门；非团队公海为空。
- `assign_blocked_until`：冷却截止时间。

索引：`idx_client_sea_scope(sea_level, sea_dept_code, owner_staff_code, status)`。

## 从参考项目吸收、后续继续实施

- 认领的 Redis 短锁与数据库乐观更新双保险。
- 批量认领/分配/回收单次不超过 500，整批事务失败回滚。
- 客户持有上限与每日认领上限参数化。
- 分配流水保留最近 N 条并由定时任务清理过期冗余记录。
- 回收记录补来源任务、入口、原跟进状态，用于审计和回退。

## 批量导入导出权限

- 仅老板、超级管理员（`SUPER_ADMIN/SUPER`）可批量导入产品、客户线索，下载导入模板并导出导入结果。
- 运营、部门经理、顾问、渠道、客户均无批量导入导出权限；前端隐藏，后端角色守卫强制拒绝。
- 产品导入按银行、产品名称、客群组合查重；线索按手机号、企业信用代码、个人身份证号硬查重；同名只警告。
- 文件内先去重、数据库按批查询，禁止逐行查询；单批最多 500；错误行保留原因用于结果导出。
