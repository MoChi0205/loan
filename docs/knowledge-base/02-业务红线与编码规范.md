# 业务红线与编码规范

## 数据与展示

1. Web、小程序和 H5 不展示物理主键、客户编码、员工编码、部门编码、报告编号等内部业务 ID；页面显示名称或可理解的业务信息。
2. 表间逻辑关联使用稳定的唯一业务 ID，不使用自增主键表达跨表业务关系；自增主键只作为表内技术键。
3. 普通页面手机号统一显示前三位、星号和后四位；明文只能经敏感查看流程返回，禁止进入列表、日志、URL和普通报表。
4. `phone` 保存 AES 密文；`phone_plain` 仅供受限内部服务读取，禁止返回 Web、小程序、H5或开放给普通数据库账号。
5. 客户材料和个人信息只用于客户主动填写、授权上传及明确授权的数据提供行为；不得虚构外部查询、OCR 结果或一致性核验。

## 合规边界

- 客户报告只提供企业经营分析、风险提示和优化建议，不展示银行产品、准入规则、匹配结果或“可通过”承诺。
- 银行规则驱动的匹配属于内部效率工具；渠道合作、可能适配产品和进件参考只在员工内部报告展示。
- 客户资料提供给银行前必须取得针对该数据提供行为的有效授权。
- 报告固定说明：`本报告仅使用客户主动填写及授权上传材料；未调用外部个人信息查询接口。`

## 工程红线

- 本机不启动或依赖本地 MySQL、Redis、Nacos、OSS/COS 模拟服务或 Docker。
- 后端启动必须显式传入 Nacos 地址和命名空间；基础设施配置只从所选 Nacos 的 `application.properties`、group `loan` 获取。
- 迁移前读取当前 Nacos 的真实数据源；不得假定 `127.0.0.1:3306/loan_db`。
- 新接口默认拒绝未识别身份，并同步菜单、接口清单、角色授权、对象权限和测试。
- 文件修改保留用户已有改动；数据库和外部配置的变更必须有可重复执行脚本。

## 编码长度三层防线（2026-10-21 用户立规）

1. **前端限长提示**：用户可输入的编码字段，输入框必须 `maxlength` + `show-word-limit` + placeholder 写明上限；表单 rules 另加 `{ max: N }` 兜底（原生 maxlength 不拦截 JS 赋值/回填）。
2. **后端显式校验**：保存入口用 `FieldLengthGuard.requireMaxLength("字段名", value, max)` 校验，上限与 `db/loan-db-schema.sql` 列宽一致，超长抛 `BusinessException(PARAM_ERROR)` 给出「字段 + 上限 + 当前长度」。
3. **禁止静默截断**：任何情况下不得对用户输入做 substring / abbreviate；MySQL 严格模式会抛 `Data too long` 原始 SQL 错误，非严格模式会悄悄截断造脏数据。服务端自动生成编码按目标列宽用 `BizIdGenerator.generate(prefix, totalLength)` 定长生成。

## SQL 实现与耗时

- 业务 SQL 不使用 `@Select`、`@Insert`、`@Update`、`@Delete` 注解；查询、写入和条件状态流转统一使用 MyBatis-Plus `Wrapper` / `LambdaWrapper`。
- 当前项目处于开发阶段，不保留旧 Mapper 方法、兼容回退或双写路径；代码、测试和文档只维护当前实现。
- SQL 耗时由 `SqlDurationInterceptor` 统一采集，只记录 statement 名称、操作、耗时和成功状态；禁止输出 SQL 原文、手机号、业务 ID、token、密钥或绑定参数。
