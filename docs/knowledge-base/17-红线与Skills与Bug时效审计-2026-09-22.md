## 4. 蒸馏进知识图的映射建议（不合并）

为兑现你的目的——**数据蒸馏 → 专属知识库**，且**不随意合并**，蒸馏时遵循：

1. **每条记录 = 独立节点**：
   - 每条业务红线 → `kind:"spec"` 或 `kind:"risk"` 节点，带 `verifiedAt` + `sourceCommit` + 源文档路径。
   - 每个 skill → `kind:"spec"` 节点（指向真实 skill 路径，引用而非复制内容）。
   - 每条 bug / C 结论 → `kind:"risk"` 或 `kind:"feat"` 节点。
2. **禁止合并**：不要把多条红线塞进一个节点；不要因为「同属 Web」就把 `Login.vue` 修复与 design-system 令牌化合为一个。

4. **真实连线**：节点间用真实 `links`（如 红线#2 → `loan-service-ops` skill 的「禁 @Scheduled」说明），不做假设性关联。
5. **先补齐基线再蒸馏**：当前知识库落后代码 8 天，直接蒸馏会丢失 09-14→09-21 全部新结论。建议先把 §0 列出的新功能回写知识库，再做蒸馏。
