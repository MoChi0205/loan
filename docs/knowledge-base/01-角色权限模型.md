# 01 · 角色权限模型

## 7 角色体系（必须严格区分）

| 角色 | userType | roleCode | 主要场景 |
|------|----------|----------|---------|
| 客户 | CUSTOMER | （无） | 自助使用小程序 |
| 渠道合作方 | CHANNEL | （无） | 录入产品 / 录入线索（沙箱隔离） |
| 顾问 | STAFF | ADVISER | 替客户匹配 / 全量陪访 |
| 部门经理 | STAFF | DEPT_MANAGER | 同顾问 + 团队归属 |
| 老板 | STAFF | BOSS | 同顾问 + 全量 |
| 运营管理员 | STAFF | OPERATOR | 配置/审批/审计；**小程序侧承载轻，主体在 Web** |
| 超级管理员 | STAFF | SUPER_ADMIN | 同运营 |

> **关键**：C1 已确认「客户（自身）+ 全部企业员工（STAFF，渠道除外）均可操作智能匹配」；**渠道合作方是唯一不可操作匹配的角色**。

## 后端：LoanUser 字段

```java
com.loan.context.LoanUser {
  Long userId;
  String userNo;          // 员工工号（员工）或 clientCode（客户）
  String phone;
  String name;
  String userType;        // CUSTOMER / CHANNEL / STAFF
  String referrerNo;
  String referrerName;
  String region;
  String avatar;
  String roleCode;        // 仅 STAFF 有：ADVISER/DEPT_MANAGER/BOSS/OPERATOR/SUPER_ADMIN
  String deptCode;
}
```

- 通过 `@ControllerUser` 注解 + 拦截器注入。
- 前端通过 `/api/mini/me` 拿到 user（注意：小程序端 user 包含 userType + roleCode）。

## 前端：Pinia store（store/user.js）

```js
state: {
  token, clientCode, user, profile,
  invitedFlag, authStatus,           // UNAUTHED / ENTERPRISE / PERSONAL
  referrerName,
  role: 'customer' | 'channel' | 'adviser' | 'deptmgr' | 'boss' | 'operator' | 'super'
}

getters: {
  isLoggedIn,                        // !!token
  isAuthed,                          // authStatus !== 'UNAUTHED'
  isChannel,                         // role === 'channel'
  isStaff,                           // ['adviser','deptmgr','boss','operator','super'].includes(role)
  roleLabel                          // 用于「我的」页与徽章
}
```

### 角色推导（resolveRole）

`userType=CUSTOMER` → customer
`userType=CHANNEL` → channel
`userType=STAFF` + roleCode → adviser / deptmgr / boss / operator / super
`roleCode` 未识别 → adviser（最小可用权限兜底）

### 角色持久化

- storage key：`loan_role`（同 token 的 loan_token）
- `/api/mini/me` 返回 `roleInfo`（含 userType + roleCode + role）
- `setUser` / `init` / `refreshProfile` 触发角色写入与持久化

## 角色化导航（C17）

- 自绘 `components/TabBar.vue`，`store.role` 驱动 tabList
- **客户/员工**：5 tab（首页·智能匹配·我的报告·服务单·我的）
- **渠道**：4 tab（首页·我的产品·录入客户·我的），隐藏匹配/报告/服务单
- 切换一律 `uni.reLaunch`（**禁用 `uni.switchTab`**，无 tabBar 配置会失败）

## 常见错误

| 现象 | 原因 | 排查 |
|------|------|------|
| 客户视角看到全部功能 | `store.role` 默认为 customer 但 getter 误判 | 检查 `isStaff` getter，role 必须是字符串数组包含项 |
| 渠道被允许匹配 | `isChannel` 未在 match 守卫 | 在 `MiniMatchService.run` 前加 `requireChannelGuard()` |
| 切换用户后菜单不变 | 切换没触发 reactive 重渲 | `pickRole` 后需 `store.setUser(data.user)` 触发 role 更新；reLaunch 后新页面读 store 渲染 |
| 渠道显示员工 tab | TabBar.vue 的 `store.isChannel` getter 没拿到最新值 | Pinia getter 引用 `state.role`，state 写入必须 `this.role = ...`（不能 `this.$state.role`） |
