## 结论

0. **TabBar 角色化结构以 D74 为准**（在 D70「按原型代码」基础上二次合并）：客户 5（首页·智能匹配·我的报告·服务单·我的）/ 渠道 4（首页·线索录入·我的客户·我的）/ 顾问·部门经理 4（首页·线索录入·我的客户·我的）/ 运营 5（含审批中心）/ 老板·超管 5（含智能匹配）；配置唯一来源 `loan-mini/utils/roles.js`。**「录入线索 + 录入产品」合并为「线索录入」，「我的客户 + 我的报告」合并为「我的客户」**，各角色 tab 一律 ≤5。D70 ② 的 5/4/5/5/6 结构与 D73 ④「小程序不承载我的客户」表述均已作废。
   - 员工侧「我的客户」= **仅本人归属**（用户 2026-09-10 确认，不放大团队/全司）；「公海」页签按 `15-客户公海团队客户与分配回收规则` §11/§12/§17 —— 公司公海全员可认领、团队公海仅本部门。
   - 渠道「我的客户」**只读**本人录入客户，无公海、无认领、无编辑、无报告入口（D50 不变）。
   - 无 mini 页的能力（团队客户 / 客户总览 / 短信 / 组织 / 权限 / 客户分析报告）仍统一提示「请在 Web 管理端使用」。
1. **客户/渠道两端的核心闭环已完整**（匹配/报告/诊断/工单/产品）。
   - 分享引荐与服务顾问是两条独立关系：邀请码只建立引荐链，不能自动写入服务顾问归属。
   - 客户顾问服务暂放在小程序「我的」，只展示 `ownerStaffName`；服务单详情同样只展示姓名。
2. **员工侧缺口集中在「管理类功能」**：
   - ✅ **审批中心入口已存在**（修正陈旧结论）：`pages/approval/list.vue` + `mine.vue` 入口，复用 C19 待审列表 + approve/reject；当前四类审批均已开放，部门经理的 ALLOCATION 仍限本人团队。原「小程序没有入口页 / 审批中心无入口」表述已不成立
   - ✅ **「我的客户」与「客户公海」已在小程序落地**（D74，修正本条原「小程序不承载公海列表」表述）：员工侧本人归属客户列表 + 公海认领；渠道侧只读本人录入客户。**管理类动作**（团队客户、客户总览、管理指定顾问、批量分配回收）仍只在 Web。
3. **「角色切换不切菜单」**：
   - auth.vue 的企业/个人切换是**认证类型**，不改变角色 → 菜单不变是预期
   - index.vue dev 面板切换 customer/staff/admin/boss 会真正改变 `store.role` → TabBar 应随之变化
   - 若 dev 切换后菜单没变，检查：① `/api/mini/me` 返回的 `roleInfo.role` 是否覆盖了本地推导（以服务端为准的设计）；② token 是否过期导致 /me 返回 customer

## 建议优先级（如果补员工侧功能）

1. 完善 Web 未分配客户池与审批中心的端到端交互测试。
2. 小程序保持只读展示顾问姓名，不增加客户手工填写邀请码或选择顾问入口。
3. 公海认领已在**小程序**提供（D74）；**管理指定顾问、批量分配/回收仍放 Web**，避免小程序重复建设管理界面。
