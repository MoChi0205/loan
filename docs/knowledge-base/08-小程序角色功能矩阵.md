## 结论

1. **客户/渠道两端的核心闭环已完整**（匹配/报告/诊断/工单/产品）。
2. **员工侧缺口集中在「管理类功能」**：
   - ✅ **审批中心入口已存在**（修正陈旧结论）：`pages/approval/list.vue` + `mine.vue` 入口，复用 C19 待审列表 + approve/reject；T5 进一步统一为产品/下载/分配三类合一入口（白名单先开 ALLOCATION，见 09-M_ALLOC 扩为审批中心）。原「小程序没有入口页 / 审批中心无入口」表述已不成立
   - ❌ 客户管理列表、❌ 线索公海：规划在 Web 端（阶段二），小程序可后续追加轻量入口
3. **「角色切换不切菜单」**：
   - auth.vue 的企业/个人切换是**认证类型**，不改变角色 → 菜单不变是预期
   - index.vue dev 面板切换 customer/staff/admin/boss 会真正改变 `store.role` → TabBar 应随之变化
   - 若 dev 切换后菜单没变，检查：① `/api/mini/me` 返回的 `roleInfo.role` 是否覆盖了本地推导（以服务端为准的设计）；② token 是否过期导致 /me 返回 customer

## 建议优先级（如果补员工侧功能）

1. **审批中心入口**（最高价值）：小程序 mine 页给 OPERATOR/SUPER_ADMIN/BOSS 加「分配审批」入口 → 复用 C19 的 pending 列表 + approve/reject 接口，加一个简单页面即可
2. **客户管理（轻量）**：员工查看「我归属的客户」列表（复用 search/claim 接口 + 新 list 接口）
3. 线索公海 / 回收：等阶段二 Web 端落地后再考虑
