## 2. 后端查询与复用审计

| 编号 | 位置 | 现状 | 风险 | 处理级别 |
|---|---|---|---|---|

| Q02 | `OrgService.pageStaff` | 每次员工分页全量查询部门、角色 | 高频翻页重复查稳定字典 | P0：缓存部门/角色只读快照并写后失效 |

| Q06 | `StrategyTemplateService`、`RuleTemplateService`、`BlacklistService` | 外部路径仍接受 `Long id` | 业务 ID 规范冲突 | P0：模板使用已有 `templateCode`；黑名单需先核对是否已有业务编码，无唯一编码则进入数据库确认闸门 |
| Q07 | `PlanOrchestrationService` | 模块/步骤内部关系仍使用物理 ID | 属持久层内部关联；是否外露需逐接口核对 | P1：仅外部接口迁移业务编码，内部 FK 暂保留 |
| Q08 | `ClientService` 详情 | 详情中逐条查邀请、引荐人、顾问 | 单详情调用可接受，但不可复用到列表 | 保留；列表装配禁止调用该方法循环查询 |
| Q09 | `MiniOrderService.allOrders` | 客户筛选先查全量 code 再 `IN` | 大客户量时 IN 集合可能过大 | P1：改 Mapper 联表/EXISTS 分页或限制候选量并补索引证据 |
| Q10 | `ApprovalService` | 产品/下载/分配三类统一页为分段分页 | total 不是全局连续页语义 | 保留现契约；前端必须按 `SEGMENTED` 处理，后续可新增游标统一流而非暗改 |

本批已落地：`PageParams` 统一所有分页 Controller 的页码/大小边界；模板主资源详情、更新、删除、发布、下线和导入改按 `templateCode`；规则模板、策略模板新增 `/batch` 批量查询，最多 100 条、去重、保序并忽略未命中项。模板内部模块/步骤/字段的物理 FK 暂保留，避免无业务编码时擅自改表。

### `selectById` 分类

- 允许保留：模块、步骤、版本等只在聚合内部使用的物理 FK。
- 必须迁移：Controller 直接接收物理 ID 的策略模板、规则模板、黑名单操作。
- 需确认数据模型：没有现成业务编码列且要对外稳定引用的关系实体；必须先设计列、唯一索引和回填脚本。
- 关联历史主键：邀请表 `referrerId` 是历史内部关联，读取可保留；新契约应优先保存并查询业务编码。

## 3. 缓存候选与禁止项

| 数据 | 更新频率 | 一致性 | 敏感性 | 策略 |
|---|---:|---:|---:|---|
| 角色菜单树 | 低 | 写后立即失效 | 低 | Caffeine 30 秒 + Redis 120 秒，按 roleCode 分键 |
| 部门树 | 低 | 写后立即失效 | 低 | Caffeine 30 秒 + Redis 120 秒 |
| 角色列表 | 极低 | 写后立即失效 | 低 | 同上；补齐角色维护入口失效 |
| 字典项 | 低 | 写后失效 | 低 | 第二批接入，按 dictType 分键 |
| 产品基础摘要 | 中 | 审批/上下架后失效 | 低 | 有接口耗时证据后接入，不缓存管理端组合分页 |
| API 权限快照 | 中 | 权限保存后立即失效 | 高 | 延续专用缓存；需统一 key/TTL/指标后再迁移 |
| 客户归属 | 高 | 强一致 | 高 | 禁止缓存 |
| 审批状态/待办计数 | 高 | 强一致 | 中 | 默认不缓存；只允许极短聚合缓存并需事件失效证据 |
| 验证码、登录会话 | 高 | 强一致/安全 | 高 | 继续使用 Redis 专用实现，不进入通用业务缓存 |
| OCR 原文、证件号、手机号明文 | 中 | 安全优先 | 极高 | 禁止通用缓存与日志输出 |

通用缓存规则：键带版本；Caffeine 一级短 TTL、Redis 二级长 TTL；同 key single-flight；Redis 故障降级；TTL 加抖动；写成功后双层失效；当前不缓存空值，避免新记录短时不可见。

## 7. 阶段验收与重启纪律

1. 每批先跑后端单测、Web 单测/构建、小程序单测/H5/微信构建。
2. 单元阶段不连接 Nacos；真实联调只使用 JDK 8 + Nacos `prd`。
3. 同一批问题先集中记录再修改，静态测试全绿后只统一重启一次。
4. 真实回归记录 HTTP 状态、业务 code、traceId、角色、数据范围、缓存命中/回源和原始错误。
5. 阻断/严重问题归零；一般问题必须有编号、影响、下一批入口和用户确认状态。
