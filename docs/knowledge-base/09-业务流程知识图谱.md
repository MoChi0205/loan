## 3. 模块节点（12）与主线流程（FLOW_SEQ）

```
                         ├─(客户/员工)─▶ M_MATCH ──▶ M_ALLOC(员工替客:查重→归属流转)
                         │                  └─▶ M_REPORT ──▶ M_PRODUCTS(员工)
                         │                                  ├─▶ M_DIAG
                         │                                  └─▶ M_ORDER
                         └─(渠道)──────▶ M_CHANPROD ──▶ M_ALLOC(删除终审待运营/老板批)

```

## 4. 状态机节点（3）

### 4.1 SM_MATCH 匹配结果态 `totalResult`
`PASS` / `CONDITION` / `REJECT` / `SKIP_SEGMENT_MISMATCH` / `ERROR`

### 4.2 SM_PRODUCT 渠道产品状态机（C9，复用 `t_product_approval`）
```
DRAFT ──submit──▶ PENDING ──(终审通过)──▶ OK
  ▲                   │                      │
  └────revoke─────────┘             delete-apply
                                   │
                              PENDING_DELETE ──audit(approve)──▶ 物理删除(软删+审计)
                                   │──audit(reject)/delete-cancel──▶ OK
```

### 4.3 SM_ALLOC 客户归属流转（C2/C19，审批动作已统一为 UA3）
```
情形A 录入即归属 / 情形B有归属人自动归属 ──▶ AUTO_CLAIMED
情形B 无归宿申请分配 ──▶ PENDING_APPROVAL ──approve(UA3,原M8)──▶ APPROVED(归属流转)
                                            └──reject(UA3,原M9,opinion必填)──▶ REJECTED
```

## 6. 关键边（CAN_ACCESS 红线摘录）

- R2(渠道) → M_MATCH / M_REPORT / M_PRODUCTS / M_ORDER ：**全部 FORBIDDEN / 隐藏**（沙箱隔离）。
- R2(渠道) → M_LEAD ：**ALLOWED**（渠道走 Lead 录入线索，沙箱隔离进公海，不进 Client；见 C20）。
- R4(部门经理) → M_ALLOC ：ALLOCATION **不可**审批（仅 OPERATOR/SUPER_ADMIN/SUPER/BOSS）；PRODUCT/DOWNLOAD 含 DEPT_MGR（白名单 `loan.mini.approval.types=ALLOCATION` 当前仅开 ALLOCATION，见 C22）。
- R1(客户) → M_PRODUCTS ：**FORBIDDEN**（对客仅返数量+评级，不返 productName/bankName，合规红线）。
- R1(客户) → M_REPORT ：后端强制**仅自己 + 仅日期**，前端传的跨用户参数一律忽略。
- R5/R6/R7(老板/运营/超管) → M_ALLOC ：拥有**审批入口**（C19 后端 M7–M9 已迁至统一 MiniApprovalController: UA1/UA2/UA3，T5 就绪；小程序 `pages/approval/list.vue` + `mine.vue` 入口已存在，见 08）。
- R4i(诊断) → t_ocr_record ：**READS**（`materialVersion` 由 `data_json._ocrMeta.version` 派生；OCR 回灌仅补空不覆盖，见 C21）。
- M_MATCH ──**OCR回灌**──▶ M_DIAG（T2：上传材料经 `MiniUploadController → MiniMaterialService → SubmissionFactsMerger.mergeFromOcr` 回灌诊断 facts，`mergeFromOcr` 仅补空、写库 `for update` 防并发）。

## 7. 消费方式

- **流程图渲染**：`artifacts/企融通业务流程图.html` 直接依据本图谱的 `FLOW_SEQ` + `statemachines` 绘制。
- **影响面分析**：改某接口 → 查 `HAS_API` 反推模块 → 查 `CAN_ACCESS` 看受影响角色 → 查 `READS/WRITES` 看数据表。
- **程序消费**：读取 `09-业务流程知识图谱.json`，按 `nodes/edges` 直接构图（节点 id 跨文件一致：R*=角色, M*=模块, A/M/R/O/P/I/W/L/U*=接口, T*=表, SM*=状态机）。
