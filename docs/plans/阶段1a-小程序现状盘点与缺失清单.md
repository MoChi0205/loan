## 二、缺失逻辑清单（问题 / 位置 / 期望行为 / 依据结论）

### M1【P0】员工替客匹配入口被「未认证」守卫拦截 —— C1/C2 全断
- **问题**：`store.isAuthed` 由 `/api/mini/me` 的 `profile.authenticated` 推导（`resolveAuthStatus`），而员工（STAFF）的 userNo 是工号，`MiniAuthService.myProfile(工号)` 查不到客户档案返回空 map → `authStatus=UNAUTHED` → `isAuthed=false`。
- **位置**：
  - `pages/match/match.vue` L8 `v-else-if="!store.isAuthed"` 守卫卡 → 员工进入匹配页永远看到「完成身份认证后即可发起智能匹配」，无法进入步骤 0
  - `pages/home/home.vue` L224 `onMatch()` 同样拦截员工；L26/L16 员工还看到「完成身份认证」引导卡与认证 pill
- **期望**：认证守卫只对 `customer` 角色生效；员工/渠道之外的角色直接进入步骤 0 替客匹配。
- **依据**：C1「客户（自身）+ 全部企业员工（STAFF，渠道除外）均可操作智能匹配」。

### M2【P0】员工报告详情 403 —— C3/C4/C5 员工视角全断
- **问题**：`/api/mini/report/{reportNo}` 后端用 `requireClient(user)`（只取 userNo 非空）并把 userNo=工号 传给 `miniDetail`，`ReportQueryService.miniDetail` 做 `clientCode.equals(report.clientProfileCode)` 归属校验 → 员工必然 FORBIDDEN「无权查看该报告」。
- **位置**：`MiniMatchController.reportDetail` L176-180；`ReportQueryService.miniDetail` L55-57；前端 `pages/report/detail.vue` onLoad catch 后显示「报告不存在或无权查看」。
- **期望**：员工角色（STAFF）跳过客户归属校验（走「全量可看」语义，同 allReports）；仅客户校验归属。
- **依据**：C3 员工可查全量报告；C4 员工可查看命中产品；C5 员工可查看诊断。

### M3【P0】员工工单详情 403 —— C7 半断
- **问题**：`/api/mini/order/{orderNo}` 同样 `requireClient` → `myOrderDetail(orderNo, 工号)` 归属校验失败 → 员工 FORBIDDEN。
- **位置**：`MiniOrderController.detail` L85-89；`MiniOrderService.myOrderDetail` L262-272；前端 `pages/order/detail.vue`。
- **期望**：员工角色跳过归属校验（列表已按全量语义返回）。
- **依据**：C7 员工可查全量工单。

### M4【P0】后端 /match/run 忽略前端 clientCode —— 替客匹配报告归属错误
- **问题**：前端 `match.vue onSubmit` 发送 `clientCode: targetClientCode.value`（员工已选目标客户），但 `MiniMatchController.run` 只读 facts/applyCity/clientSubmitId，`requireClient(user)` 返回员工工号并作为 clientCode 传入 `runForMini` → 报告落在员工本人（工号）名下，且 `requireAuthenticated(工号)` 大概率报「客户档案不存在」，**员工替客匹配即使入口放开也会失败或归属错误**。
- **位置**：`pages/match/match.vue` L491-497（传参）；`MiniMatchController.run` L50-57（忽略）；`MiniMatchService.runForMini` L88-105。
- **期望**：后端 run 增加 `clientCode`（目标客户）可选参数：员工传参时以目标客户为归属/校验对象；客户不传时用登录态。
- **依据**：C2「匹配只能在『我归属的客户』上发起」。

### M5【P0】产品编辑不可用 —— C9 断裂
- **问题**：`product/edit.vue onLoad` 只记录 `code`，**表单不回填**（显式 TODO）；且编辑态 `bankProductCode` 输入框 `:disabled="isEdit"` 且为空 → 用户打开编辑页看到空表单且无法输入编码；后端 `MiniProductController.update` 也忽略路径 `code`，直接 `save(body)` 按 bankProductCode 幂等 → 「编辑」实际是「按编码重建草稿」。
- **位置**：`pages/product/edit.vue` L92-98（TODO）、L11（disabled）；`MiniProductController.update` L76-83。
- **期望**：新增 `GET /api/mini/product/{code}` 详情回填；编辑保存携带 code；后端 update 按 code 定位审批单。
- **依据**：C9 状态机「DRAFT/REJECTED 可编辑重提」。

### M6【P1】C19 无归宿分配审批前端零落地
- **问题**：后端 `GET /api/mini/client/allocation-approvals/pending`、`POST .../approve`、`POST .../reject` 已就绪（权限 OPERATOR/SUPER_ADMIN/SUPER/BOSS），但前端 `api/client.js` **未封装**、无审批入口页、mine.vue 无入口 → 运营/超管/老板无法在手机上批分配。
- **位置**：`api/client.js`（缺 3 方法）；`pages/mine/mine.vue`（无入口）；`pages.json`（无审批页）。
- **期望**：api/client.js 增加 pendingAllocations/approveAllocation/rejectAllocation；mine.vue 对 boss/operator/super 增加「分配审批」入口 + 待审列表页（复用 C19 接口）。
- **依据**：C19-B3；08 矩阵「无归宿分配审批：🟡 审批中心无入口」。

### M7【P1】C9 产品删除终审前端零落地
- **问题**：后端 `GET /api/mini/partner-product/delete/pending`、`POST /api/mini/partner-product/delete/{approvalNo}/audit` 已就绪，前端 `api/product.js` 未封装、无运营侧入口 → 渠道发起的删除申请在小程序端无人可批（只能去 Web 管理端）。
- **位置**：`api/product.js`；`pages/mine/mine.vue`（运营/超管无删除审批入口）。
- **期望**：运营/超管在「我的」页增加「产品删除审批」入口 + 待删列表/通过/驳回页。
- **依据**：C9「删除（申请下架）→ 我司运营/超管终审」；C14 曾标注「删除审批流断裂」。

### M8【P1】经营材料上传未实现（4 个占位）
- **问题**：`match.vue onUpload/onSupplement`、`report/detail.vue onUploadMaterial` 均只 `showToast`；`utils/wx.js` 已有 `uploadImage/chooseAndUpload` 但页面未引用；步骤 2 的 4 个材料瓦片是硬编码静态数据（status 写死）。
- **位置**：`pages/match/match.vue` L386-400、L403-407（verifyList 也是静态假数据）；`pages/report/detail.vue` L316-318。
- **期望**：接入 uni.chooseImage/uni.uploadFile + 后端附件接口，真实上传；verifyList 依据上传结果渲染。
- **依据**：C5「复用匹配已上传材料生成诊断；材料非最新提示上传最新材料」；C2 情形 A 步骤 3「上传经营材料」。

### M9【P1】AppButton 组件 API 不一致 —— 全站次按钮样式失效
- **问题**：`components/AppButton.vue` 只声明 `type` prop（primary/ghost/text/gold），但 **22 处页面调用全部传 `variant="..."`**（`variant` 未被声明 → 透传为 button 属性，`type` 默认 primary）→ 「secondary/ghost 描边按钮」全部渲染成主按钮深蓝实心，仅 `order/detail.vue` 用的 `type="primary"` 碰巧生效。知识库 05 也把用法写成 `variant`（文档与实现互相矛盾）。
- **位置**：`components/AppButton.vue` L33-40；`pages/*` 22 处 `variant=`；知识库 05 §常用组件 API。
- **期望**：统一为 `variant`（推荐改组件以匹配设计系统文档），或全局替换为 `type`；删除矛盾文档。
- **依据**：05-前端工程要点、设计系统规范（variant 语义）。

### M10【P1】员工/渠道进入「我的」页触发邀请/奖励接口报错
