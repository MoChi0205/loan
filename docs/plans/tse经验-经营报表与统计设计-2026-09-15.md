# TSE 经验：经营报表与统计设计建议（2026-09-15）

## 一、先统一统计范围

报表不使用“公司客户”作为单一统计口径，而按客户归属范围切换：

| 范围 | 客户过滤 | 适用角色 |
|---|---|---|
| 我的 | `owner_staff_code = 当前工号` | 顾问、部门经理、运营、老板、超管 |
| 团队 | `owner_staff_code IN 本部门在职员工` | 部门经理 |
| 全司 | `owner_staff_code IS NOT NULL` | 老板、运营、超管 |
| 公司公海 | `sea_level = ENTERPRISE AND owner_staff_code IS NULL` | 公司员工 |
| 团队公海 | `sea_level = TEAM AND sea_dept_code = 当前部门` | 本部门员工 |

线索统计同时保留两个维度：`recorder_staff_code`（谁创建）和 `owner_staff_code`（当前谁负责）。这样能区分“获客贡献”和“跟进责任”。

## 二、建议建设的 5 组报表

### 1. 客户资产与公海效率

- 当前客户总量：我的 / 团队 / 全司
- 已分配客户数、公司公海数、团队公海数
- 公海新增、认领、回收、再次分配
- 公海平均停留时长、最长停留时长
- 公海认领率 = 认领客户数 / 进入公海客户数
- 冷却期客户数（`assign_blocked_until > now()`）

### 2. 线索到成交漏斗

建议按创建月份或日期 cohort 统计，而不是只看累计总数：

`新增线索 → 已分配 → 已转客户 → 已生成初筛 → 已建工单 → 已成交 → 已发放奖励`

每一层展示：数量、环比、转化率、平均耗时。线索需同时按创建人和当前归属人拆分。

### 3. 顾问 / 团队绩效

- 新增线索数（按创建人）
- 当前负责客户数（按归属人）
- 有效跟进客户数
- 待跟进、即将超期、已超期客户数
- 初筛报告数、工单数、成交单数、成交金额
- 客户转化率、工单成交率、平均首响时长
- 回收客户数与回收原因

部门经理只看本部门；老板、运营、超管看全司。顾问不应看到其他顾问的明细。

### 4. 服务质量与 SLA

利用现有 `last_followed_at`、`next_follow_time`、`created_at`、`deal_time`：

- 新线索首次跟进时长
- 客户平均跟进间隔
- 超期未跟进客户数
- 即将触发自动回收客户数
- 自动回收 / 主动释放 / 经理回收数量
- 工单从新建到服务中、服务中到成交的平均时长

### 5. 经营结果与收益

- 成交单数、成交金额、客单金额
- 按产品、客群、团队、顾问分布
- 奖励单数、奖励金额、奖励发放率
- 线索来源（员工 / 老板 / 渠道 / VIP）与最终成交贡献
- 产品匹配命中率、初筛通过率、报告到工单转化率

## 三、推荐页面结构

### 经营概览

保留当前已有的客户、线索、工单、成交、奖励、初筛指标；新增“客户范围”切换：

`我的｜我的团队｜全司｜公司公海｜团队公海`

角色只能看到有权限的范围。

### 客户运营分析

新增客户资产、公海效率、分配回收、SLA 四个区块。

### 团队绩效

部门经理看到本部门顾问排行；老板/运营/超管看到全司排行；排行榜同时展示数量指标与转化率，避免只按成交金额排名。

### 漏斗与趋势

趋势统一支持日 / 周 / 月，漏斗按 cohort 计算，避免“本月新增线索”和“累计成交客户”直接相除造成误导。

## 四、TSE 可复用的工程经验

1. 统计范围必须后端强制，不只隐藏前端筛选项。
2. 指标使用聚合 SQL，不把全量客户拉到前端计算。
3. 实时看板使用快照或小时桶，避免高峰期重复扫大表。
4. 所有指标固定枚举和时间边界，明确“创建时间、归属时间、成交时间”不可混用。
5. 报表菜单、路由、API、角色权限和数据范围要一起验收。

## 五、当前系统的落差

- 已有：经营概览、成交/奖励月趋势、基础漏斗、客群/产品/工单分布、角色范围过滤。
- 已有字段可支撑：客户归属、公海层级、创建人、最后跟进、冷却截止、工单成交时间、奖励金额。
- 尚缺：公海停留时长、分配/回收效率报表、顾问绩效排行、SLA 预警明细、cohort 漏斗、首响耗时。
- 需要先确认：部门经理是否可看“团队绩效排行”中的顾问明细，以及运营是否需要全司绩效明细。
