# 管理端计划编排与步骤弹窗规则联动需求

> 日期：2026-09-06 ｜ 状态：已实施（D56） ｜ 关联技能：loan-web-ui、loan-web-components、loan-knowledge

## 一、需求来源

用户在管理端（loan-web）联调过程中，针对计划编排页和策略模板编辑步骤弹窗提出多项交互与数据问题，分两轮反馈：

- **第一轮**：计划编排页列拖拽、日期排序、弹窗分模块展示、行操作按钮
- **第二轮**：策略模板编辑步骤弹窗的规则联动 4 个问题 + 计划编排页数据隔离与 UI 一致性

## 二、需求清单与实施结论

### 需求 1：计划编排页列可拖拽 + 日期列排序

| 项 | 结论 |
|---|---|
| 列拖拽 | el-table 表头引入 `sortablejs`，支持列左右拖拽横移；操作列 `fixed="right"` 不参与拖拽 |
| 日期排序 | 新增创建时间、更新时间列，列头 `sortable="custom"` 支持升/降序箭头 |
| ⚠️ 遗漏 | 当前排序为**客户端当前页排序**（handleSortChange 在 plans.value 上 sort），未走 useTable 的 @sort-change 跨页后端排序。loan-web-ui 第四条要求"跨页生效（query.sortBy/sortDir 传后端）"，需后续补齐 |

### 需求 2：计划编排页点击行弹窗分模块展示

| 项 | 结论 |
|---|---|
| 交互改造 | 移除原来 inline 展开所有模块步骤；改为点击行弹出「计划编排详情」AppDialog |
| 弹窗布局 | 左侧模块列表卡片（点击切换高亮）+ 右侧当前模块步骤详情表格 |
| 模块切换 | 点击左侧模块即切换右侧步骤详情，不再一次性铺开所有模块 |

### 需求 3：计划编排页行操作按钮

| 项 | 结论 |
|---|---|
| 行操作 | 操作列加入编辑、复制、另存为模板、删除四个按钮（`@click.stop` 防止触发行点击弹窗） |
| 顶部按钮 | 顶部原有的四个功能按钮保留，与行操作共用同一套逻辑（onCopyPlan/onSaveAsTemplate/onDeletePlan 接收具体 plan 入参） |

### 需求 4：策略模板步骤弹窗 — 条件字段自动带出

| 项 | 结论 |
|---|---|
| 用户原意 | 步骤条件字段、条件值应根据规则判断值自主控制，不需要前端操作时手动选择 |
| 实施 | 选择规则 `@change="onRuleChange"` 自动填充：conditionField=rule.fieldCode、conditionOperator=OP_MAP[rule.operator]、conditionValue=rule.valueText |
| 运算符映射 | `==→EQ`、`!=→NE`、`in→IN`、`not_in→NOT_IN`、`is_null→IS_BLANK`、`not_null→IS_NOT_BLANK`（对齐 StepConditionEvaluator 白名单） |
| 只读 | 三个条件字段全部 `disabled`（只读），不再手动选择 |

### 需求 5：编辑时无法回显规则名

| 项 | 结论 |
|---|---|
| 根因 | 规则下拉 `:value="r.ruleId"`（RuleDTO 无 ruleId 字段，值为 undefined），导致编辑时 ruleId 无法匹配回显 |
| 后端改动 | RuleDTO 新增 `id`、`fieldName` 字段；RuleQueryService#toDTO 补全 setId/setFieldName/setValueType |
| 前端修复 | 规则下拉 `:value="r.id"`（与后端步骤表 ruleId 外键对齐）；编辑时 ruleId 直接匹配回显 |

### 需求 6：已配置规则从下拉排除

| 项 | 结论 |
|---|---|
| 实施 | 新增 `availableRules` 计算属性：过滤掉当前模块已配置的规则（编辑模式保留当前规则自身可选） |

### 需求 7：个贷/企业贷规则按客群分开

| 项 | 结论 |
|---|---|
| 实施 | `loadRules(row.customerGroup)` 已按客群过滤（含 COMMON 通用规则）；个贷模板不会出现企业贷规则，反之亦然 |
| 后端 | listRulesForAdmin 已按 customerGroup + COMMON 联合查询 |

### 需求 8：计划编排页数据隔离 + UI 一致性

| 项 | 结论 |
|---|---|
| 数据隔离 | 后端 AdmissionExecutionPlanController#list 新增可选 customerGroup 参数；前端 loadPlans 传参按客群过滤 |
| UI 一致 | segmented 去掉 `block` 属性（原渲染全宽蓝色块），改为与策略模板页一致的 `.cg-switch` + `.cg-switch__hint` 结构 |
| URL 同步 | 切换客群时 router.replace 同步 ?cg= 到 URL（与策略模板页行为一致） |

## 三、自检遗漏（待后续补齐）

按 loan-web-ui 自检清单逐条核对，以下项未达标，需后续补齐：

1. **时间列跨页后端排序**（loan-web-ui 第四条）
   - 现状：PlanEdit handleSortChange 在 plans.value 上客户端 sort
   - 要求：sortable="custom" + @sort-change 走 useTable，query.sortBy/sortDir 传后端，跨页生效
   - 后端：listPlans / page 接口需支持 orderBy/orderDir 参数

2. **表格填充满容器**（loan-web-ui 第七条）
   - 现状：PlanEdit / StrategyTemplateList 表格未加 `height: calc(100vh - 320px)`
   - 要求：el-table 加固定高度，数据少时撑满容器不留大空白

3. **操作列宽度收敛**（loan-web-ui 第三条）
   - 现状：StrategyTemplateList 操作列 width=220（5 个操作：编排/导入/上线或下线/编辑/删除）
   - 要求：skill 建议 3+ 操作用 180，但实际 5 个操作 + AppTableActions maxInline=2 可能偏窄，需实测酌情

4. **步骤弹窗编辑模式规则下拉禁用**
   - 现状：编辑时规则下拉仍可选（onRuleChange 会覆盖已有条件字段）
   - 建议：编辑模式 `:disabled="!!stepDialog.editingId"`，并在 onRuleChange 中判断编辑模式不覆盖
