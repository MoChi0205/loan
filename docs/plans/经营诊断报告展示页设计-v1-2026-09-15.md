# 经营诊断报告展示页设计 V1

## 1. 设计目标

本页不是经营数据堆叠页，而是面向企业客户、归属顾问和管理者的单企业决策报告。阅读顺序固定为：

`结论 → 健康度 → 风险 → 经营趋势 → 融资策略 → 行动计划 → 数据依据`

参考本地大脑中的上海旭荣网络案例经验：企业资质、财务健康、司法税务、融资承载与产品策略应合并判断；不能只展示年纳税、年开票和命中产品数量。

## 2. 页面信息架构

| 层级 | 展示内容 | 使用目的 |
|---|---|---|
| 报告头 | 企业、编号、数据截止日、版本、归属顾问、材料时效 | 确定报告对象与可信时间边界 |
| 管理摘要 | 综合健康分、等级、行业位置、核心结论、融资准备度 | 30 秒完成经营判断 |
| 核心指标 | 营收、利润、开票、纳税、资产负债率及同比 | 识别规模、质量和负债压力 |
| 六维诊断 | 盈利、成长、偿债、现金流、稳定、合规 | 与行业基准比较，而非孤立看分数 |
| 风险矩阵 | 风险等级、事实依据、影响、处理建议 | 将问题按优先级收敛 |
| 历年趋势 | 营收、利润、经营现金流 | 识别有利润但缺现金、增收不增利 |
| 融资诊断 | 建议额度、期限、优先路径、产品匹配 | 连接经营事实与融资方案 |
| 行动计划 | 30/60/90 天任务、责任人、状态 | 将建议转为可执行动作 |
| 数据依据 | 已核验、OCR、待补采集 | 避免模型将缺失信息当成零值 |

## 3. 当前系统可直接使用的数据

- 企业档案、认证状态、企业名称、信用代码、成立年限。
- 年纳税额、年开票额、行业等 `t_client_submission.data_json` 经营事实。
- 初筛评级、通过/有条件/拒绝数量、命中产品和规则日志。
- `t_industry_benchmark` 行业维度基准。
- OCR 材料版本及回灌状态。
- 归属顾问、报告编号、生成时间、材料附件。

## 4. 需要扩展的数据

- 财务报表结构化：营收、毛利、净利润、总资产、总负债、流动资产、流动负债。
- 现金流和流水月度聚合：经营流入、经营流出、净现金流、回款波动。
- 应收账款：账龄、回款周期、客户集中度。
- 有息负债：余额、期限、利率、一年内到期比例。
- 历年数据与预测值需区分事实、人工确认和模型预测。

## 5. 诊断规则建议

- 健康分必须展示维度贡献和证据，不输出无法解释的黑盒总分。
- 行业对比标明基准来源；默认兜底值不能伪装成真实行业样本。
- 缺失数据展示“待补采集”，不得按 0 分处理。
- 建议必须包含影响、动作、责任人和复核时间。
- 融资额度、产品概率等使用“建议区间/匹配度”，不使用授信承诺文案。

## 6. 原型说明

原型中的旭荣网络经营数据为页面结构示例，不是系统已核验的正式财务结论。真实上线时，所有数字必须绑定来源状态：

- 绿色：系统已核验。
- 蓝色：OCR 提取，等待人工复核或已回灌。
- 空心橙色：当前系统尚未采集。
