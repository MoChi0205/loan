# 全角色登录与密码找回改造

## 已实现

- Web 员工与渠道：密码登录、**默认登录方式**、短信验证码登录、验证码找回/首次设置密码。
- H5/小程序客户：密码登录、短信验证码登录、验证码找回/首次设置密码；原微信登录保留。
- 随机验证码（2026-09-21 改版）：**服务端渲染 4 位数字图片验证码（Base64 PNG）**，Redis 保存答案 5 分钟，
  验证后立即删除（无论成功失败），答案不再随接口下发。
  实现参照 tse `CaptchaServiceImpl`（120×40 画布、干扰线与噪点、字符轻微旋转、一次性消费），
  字符集收敛为 4 位数字（1000–9999），字体使用逻辑字体 `Font.SANS_SERIF` 避免运行环境缺字体。
- 密码安全：前端 RSA PKCS#1 加密传输，服务端 BCrypt 存储；重置密码要求 8–64 位并同时包含字母和数字。
- 短信验证码：LOGIN 与 RESET_PASSWORD 分场景 Redis Key，均保留 60 秒间隔和单手机号日上限。

## 上线前操作

1. 执行 `db/migrate-auth-password-all-roles-2026-09-20.sql`。
2. 确认 `t_staff.password`、`t_client_profile.password` 已创建。
   数据库尚未迁移时，实体默认查询不读取新列，原短信验证码登录仍可使用；密码流程会等待迁移完成。
3. 现有员工/客户首次使用“忘记密码”通过短信设置密码；渠道保留现有 BCrypt 密码。
4. `scripts/run-dev-local.sh` 与本机 `scripts/service.sh` 已显式开启模拟短信验证码自动填入；应用默认配置及正式部署保持 `false`，生产接入真实短信且禁止日志输出验证码。
