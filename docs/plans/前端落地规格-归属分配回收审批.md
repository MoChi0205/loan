## 0. 后端已就绪确认（无需后端改动）

| 能力 | 后端落点 | 关键行为 |
|------|----------|----------|
| 直接指定归属（C23） | `ClientController.assign` → `ClientAllocationService.directAssign` | 立即落归属、不生成审批单；覆盖式 `assignOwnerIfUnchanged`（可重分配已归属客户）；目标角色 `ASSIGNABLE_ROLES = [ADVISER, DEPT_MANAGER]`；`touchAssignment` 刷新跟进基准+清冷却 |
| 手动回收（C26） | `ClientController.recycle` → `manualRecycle` | 清空 `owner_staff_code` + 置 `assign_blocked_until` 冷却；不删档案；`requireApprover` 门控 |
| 分配审批范围（C24） | `ClientAllocationService.pendingPage/approve/reject` | DM 仅见**本团队**（申请人 deptCode==DM deptCode）待审单；`assertDeptManagerScope` 跨团队抛 `FORBIDDEN("非本团队客户，需由 BOSS 审批")` |
| 替客匹配强制审批（C25/P0-3） | `MiniMatchService.runForMini` | 目标客户已归属他人且非本人且无 `hasApprovedOwnership` → `FORBIDDEN("该客户已归属他人，请先在「客户分配」中发起归属审批后再匹配")` |
| 归属转移申请 | `MiniClientService.claim` → `applyTransfer` | 生成 `ADVISER_TRANSFER` 待审单，走统一审批中心 |
| 员工远程搜索 | `GET /api/admin/org/staff/page` | `deptCode, roleCode, keyword, page, size, orderBy, orderDir` |

**响应字段约定**（来自源码 `Map` 返回）：

- `assign` 返回：`{ clientCode, adviserName, ownerStaffName, ownerStaffRole, status:"APPROVED", direct:true, needApproval:false }`
- `recycle` 返回：`{ clientCode, recycled:true, fromOwnerStaffCode }`
- 统一 `Result<T>`：`code=0` 成功；非 0 失败，`message` 含上述中文提示（`FORBIDDEN` 时已本地化）。

## 2. #211 · Web 客户 API（`src/api/client.js`）

后端 `/assign` body 兼容 `{targetStaffCode}`（新）与 `{adviserStaffCode}`（旧）。前端统一用新字段。

```js
import request from '@/utils/request'

/**
 * 管理端直接指定归属（D39/C23）：立即落归属、不生成审批单。
 * @param {string} clientCode 客户编码
 * @param {string} targetStaffCode 目标归属人工号（ADVISER / DEPT_MANAGER）
 */
export function assignClient(clientCode, targetStaffCode) {
  return request({
    url: `/api/admin/client/${clientCode}/assign`,
    method: 'post',
    data: { targetStaffCode }
  })
}

/**
 * 管理端手动回收进公海（C26）：清空归属 + 置冷却，不删档案。
 * @param {string} clientCode 客户编码
 */
export function recycleClient(clientCode) {
  return request({
    url: `/api/admin/client/${clientCode}/recycle`,
    method: 'post'
  })
}
```

**动作**：
- 将现有 `assignClientAdviser(clientCode, adviserStaffCode)` 调用点全部改为 `assignClient(clientCode, targetStaffCode)`（语义对齐 C23「直接指定」）。
- 在 `src/api/approval.js` 删除/修正 `ALLOC_APPROVER` 注释中「不含 DEPT_MANAGER」字样（见 #213）。

## 3. #210 · Web 档案页分配/回收弹窗（`src/views/client/ClientProfile.vue`）

### 3.1 角色门控

```js
import { assignClient, recycleClient } from '@/api/client'
import { staffPage } from '@/api/org'

const ASSIGN_ROLES = ['DEPT_MANAGER', 'BOSS', 'OPERATOR', 'SUPER_ADMIN', 'SUPER']

computed: {
  canManage() {
    return ASSIGN_ROLES.includes(this.$store.getters.role /* 或 store.role */)
  }
}
```

### 3.2 替换自由输入 `ownerStaffCode`

原档案页用自由输入框编辑 `ownerStaffCode` → 改为**只读展示** `ownerStaffName`（`detail` 接口已返回），归属操作统一走弹窗。

### 3.3 分配归属弹窗

- 触发按钮：`v-if="canManage"` 的「分配归属」。
- 弹窗内：
  - 角色单选（顾问 / 团队管理者）→ 决定 `roleCode`（`ADVISER` / `DEPT_MANAGER`）。
  - `el-select` + `remote` 远程搜索，调用 `staffPage({ roleCode, keyword, page:1, size:20 })`，选项展示 `staffName`（禁用非 ACTIVE）。
  - 选中得 `targetStaffCode`。
- 确认时**二次确认**：

```js
this.$confirm(
  `确认将客户【${this.entName}】的归属调整为「${selectedName}」？此操作立即生效，无需审批。`,
  '分配归属确认',
  { type: 'warning' }
).then(() => {
  assignClient(this.clientCode, this.targetStaffCode).then(() => {
    this.$message.success('归属已更新')
    this.loadDetail() // 刷新档案（ownerStaffName 变化）
  })
})
```

### 3.4 回收进公海弹窗

- 触发按钮：`v-if="canManage"` 的「回收进公海」（仅当 `ownerStaffCode` 存在时可用）。
- 确认：

```js
this.$confirm(
  '确认回收该客户进公海？原归属将清空，冷却期内不可认领。',
  '回收确认',
  { type: 'warning' }
).then(() => {
  recycleClient(this.clientCode).then(() => {
    this.$message.success('已回收进公海')
    this.loadDetail()
  })
})
```

> 组件复用：按 loan-web 规范用 `AppDialog` / `AppSearchBar` / `AppTableActions` 等封装组件，避免裸 `el-dialog`。

## 5. #212 · 小程序 `runMatch` 透传 clientCode + 匹配拦截 UX

### 5.1 `api/match.js` 透传 `clientCode`（P0-3 守卫依赖此字段）

```js
// 原：runMatch({ facts, applyCity, clientSubmitId }) —— 丢弃了 clientCode，导致 P0-3 守卫收不到目标客户
export function runMatch({ facts, applyCity, clientSubmitId, clientCode }) {
  return request({
    url: '/api/mini/match/run',
    method: 'post',
    data: { facts, applyCity, clientSubmitId, clientCode } // STAFF 视角 clientCode 必传
  })
}
```

> 后端 `MiniMatchController.run`：CUSTOMER 强制以登录态 clientCode 归属（忽略 body）；**STAFF 取 body.clientCode 为目标客户（必传）**，P0-3 守卫据此判定。

### 5.2 `pages/match/match.vue` 拦截 UX

`onSubmit` 捕获 P0-3 的 FORBIDDEN（message 含「归属审批」），引导至归属审批：

```js
try {
  const res = await runMatch({ facts, applyCity, clientSubmitId, clientCode })
  // ...正常渲染匹配结果
} catch (e) {
  const msg = (e && e.message) || ''
  if (msg.indexOf('归属审批') !== -1) {
    uni.showModal({
      title: '需要先发起归属审批',
      content: '该客户已归属他人，请先在「客户分配」中发起归属审批，审批通过后再匹配。',
      confirmText: '去发起',
      success: (r) => {
        if (r.confirm) {
          uni.navigateTo({ url: `/pages/client/claim?clientCode=${clientCode}` })
        }
      }
    })
    return
  }
  uni.showToast({ title: msg || '匹配失败', icon: 'none' })
}
```

### 5.3 命中卡 `hasOwner` 文案修正

步骤 0 命中已归属客户时，原文案「申请后自动归属给你（无需审批）」已不准确（P0-3 下对他人客户需审批）：

- 若当前是客户本人 / 客户归属人本人：`匹配结果将自动归属给你`。
- 若当前是员工且目标客户已归属**他人**：展示提示「该客户已归属他人，匹配需先发起归属审批」，并弱化/禁用直接提交，引导走 5.2 拦截流程。
