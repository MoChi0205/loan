## 三、仍存差异 / 缺失（本轮新发现 + 未闭环项）

### D-1【低】命中产品明细字段缺失 tags / requirement（C4 数据未全）
- **现象**：`report/detail.vue` L67/L71 渲染 `p.tags`、`p.requirement`（v-if 保护不报错），但后端 `MiniMatchService.reportProducts`（L343-353）只返回 productCode/hitResult/matchScore/productName/bankName/amountRange/rate/term，**不返回 tags 与 requirement** → 这两个字段永远为空。
- **影响**：员工查看命中产品时看不到「产品标签」与「准入要求」，与 C4「命中产品明细完整展示」不符；但前端已用 `AppEmpty` 兜底「t_screening_product 能力补齐中」，体验上不报错。
- **建议**：后端 `reportProducts` 补 tags（产品标签）与 requirement（准入要求）字段，或前端移除空渲染。

### D-2【已核实】命中产品明细 / 经营诊断的数据生产链路
- **核实结果**：`ScreeningService.execute` 在生成报告后调用 `saveScreeningProducts` 写入 `t_screening_product`；`MiniMatchService.reportProducts` 批量关联产品/银行数据返回明细。`reportDiagnosis` 已基于提交事实和报告生成 KPI、建议、风险、年度数据与行业基准维度。
- **结论**：原“算法待落地”判断基于旧核查，当前为空时仅代表该报告没有命中产品或缺少经营事实，前端空态仍应保留；无需另起一套数据生产链路。

### D-3【已实施】统一审批中心四类白名单开放
- **处理**：在现有统一审批实现与角色守卫不变的前提下，运行配置开放 PRODUCT、DOWNLOAD；小程序列表补产品名、下载申请人/用途的中文主位展示。材料复核沿用 D58 的 `reviewNo → approvalNo` 适配。
- **权限边界**：ALLOCATION 的部门经理仅能审批本人团队；PRODUCT、DOWNLOAD、MATERIAL_REVIEW 走普通审批角色范围。无需新增接口或网关授权。
- **状态**：已由 D59 落地。

### D-4【低】产品编辑保存字段与详情返回字段不对称
- **现象**：`MiniProductService.detail` 返回 `amountMin`/`amountMax`（数值），但 `product/edit.vue` onSubmit（L149-152）保存时发送 `amountRange`（字符串 "100-500万"），未发 amountMin/amountMax。
- **影响**：回填可用（读 min/max），但保存路径用 range 字符串、读取路径用 min/max，字段 shape 不一致；目前后端 save 兼容 amountRange 解析，功能可用，但契约不规整。
- **建议**：统一为 amountMin/amountMax 或后端明确只认 amountRange，回写 `api/product.js` 注释。

### D-5【低】api/order.js 状态枚举注释过期
- **现象**：`api/order.js` L25 注释写 `PENDING/PROCESSING/SUPPLEMENT/DONE/CANCELED`，但后端 `ServiceOrder` 真值为 `NEW/IN_SERVICE/DEAL/CANCEL/REFUND`（`order/list.vue` 已用正确枚举）。
- **影响**：仅文档误导，不影响功能（order/list.vue 用的是正确枚举）。
- **建议**：修正注释。

### D-6【已核实，无需修改】runMatch 控制字段未进入请求体
- **核实结果**：`match.vue` 虽向 `runMatch` 传入 `showError: false`，但 `api/match.js` 会将其从参数对象解构，并作为 `requestPost` 的第三参 options 传递；实际 POST body 不含该字段。
- **结论**：原核查结论基于旧实现，当前无需改码；已由 D55 记录。

### D-7【极低】mine.vue 残留一处裸色值
- **现象**：`mine.vue` L533 `.menu-badge color: #fff`。
- **建议**：改 `var(--text-invert)`。

## 四、设计内「不承载」确认（非缺失）

对照 `08-小程序角色功能矩阵.md`，以下在小程序端**刻意不实现**，属预期：
- 客户管理（列表/跟进）、线索公海（认领/回收）→ 放 Web 管理端。
- 未分配客户归属分配 → 小程序仅顾问发起认领审批；管理员直分配走 Web。
- 渠道禁入匹配/报告/服务单 → 沙箱隔离，TabBar 仅 4 tab。
