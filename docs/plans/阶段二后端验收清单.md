## 核查口径（重要）
1. **判定标准**：
   - ✅ **已完成**：Controller + Service + Mapper 齐全，接口覆盖纪要该功能域全部要点，且走真实 DB（非 Demo/Mock）。
   - 🟡 **部分**：有后端接口但仅覆盖功能域部分要点，缺关键写接口 / 子功能。
   - 🩲 **仅骨架**：仅有实体 / Mapper，无 Service / Controller（不可对外提供能力）。
   - ⬜ **未开始**：无相关 Java 代码（空目录或不存在）。
2. **空目录陷阱**：`dashboard / stats / blacklist / order / approval / reward / report` 这些目录**真实存在但内部无任何 Java 文件**（仅占位），属"未开始"，不是"已铺开"。
3. **前端不计入**：阶段二大量是 Web 管理端前端（loan-web），本清单只评后端；前端进度由用户掌握。
4. **真实数据验证**：已落地模块（org/lead/product/sms/audit/ocr/attachment 等）的 Service 均调用 Mapper 查/写 DB，未发现 Demo / Mock 返回占位数据。

## 逐域详述（接口 / 缺失项）

### ✅ 已完成（额外）
- **敏感数据查看授权**：`com.loan.sensitive`（实体 / Mapper / Service / Controller 齐全，接真实 DB）。

### 🟡 部分（5 域）
- **组织与权限中心**：已有菜单树、部门树、角色列表、员工分页查询；缺口 = 部门增删改、员工映射写、角色-菜单操作权限配置、审核人配置、兜底顾问池配置（均为写接口，目前无）。
- **审计中心**：已有匹配过程审计（trace 详情 + 分页）；缺口 = 操作日志审计（`t_operation_log`）未接入审计中心。
- **客户管理（含黑名单）**：线索/客户查看有；黑名单管理（多维命中查询 / 新增留痕 / 解禁仅老板）完全未开始；银行匹配明细查看依赖匹配引擎，缺专门 Tab 接口。
- **渠道用户管理 + 产品审核**：产品审核 CRUD 有；渠道用户管理（CRUD）未开始；银行渠道联系人库维护未开始（`ChannelContact` 不存在）。
- **线索公海中心**：录入 / 分页 / 认领 / 指派 / 回收 / 预警齐；缺口 = 回收规则参数配置写接口、离职转移接口。
- **短信中心**：登录验证码发送 / 校验有；缺口 = 模板管理、发送记录、回执明细、频控配置、退订黑名单（即"短信中心"管理面几乎未做）。

## 跨阶段基建（已就绪，支撑阶段二）
- `ocr`（OCR 识别骨架）、`attachment`（文件存储 / 水印骨架）—— 支撑客户上传、服务工单资料库。
- `notification`（站内消息）—— 支撑预警 / 通知触达。
- `infrastructure`（AES 加密）、`utils`（脱敏）、`log`（操作日志切面）—— 全链路安全合规底座。

## 结论
- **阶段二 14 个功能域：0 个完全验收通过，5 个部分完成，9 个未开始**（另 +1 额外完成的敏感授权）。
- 阶段二后端实际进度远低于"包目录铺开"的观感——多数模块只是空目录占位。当前真正能用的后端集中在：组织权限查询、线索公海核心流程、产品审核 CRUD、审计（匹配）、登录/渠道登录、短信验证码、OCR/文件骨架、站内消息、敏感授权。
- 建议优先级（若继续推进阶段二后端）：① 服务工单（order，阶段二体量最大）② 资料下载审批 / 奖励结算 ③ 短信中心管理面 ④ 报表中心 ⑤ 我的工作台 / 配置向导 / 报告模板 / 初筛闸门 ⑥ 补齐组织权限写接口与黑名单管理。
