# 企业经营报告双视角展示与权限方案 V1

**版本：** 2026-09-18  
**适用对象：** 客户与公司员工  
**目标：** 同一客户报告按登录身份提供两种展示视角：客户看到合法合规的经营分析；公司员工看到服务所需的内部经营判断、合作渠道和可能适配的进件产品。

> 范围说明：现有渠道合作端及其产品、报告、审批、权限和可见范围保持不变。本方案只新增客户视角与公司员工内部视角，不调整渠道合作相关功能。

## 1. 两个视角

### 1.1 客户视角：经营分析报告

客户可查看：

- 客户主动填写及授权上传材料形成的经营事实、趋势和资料完整度；
- 收支、回款、客户/供应商结构、税票流水一致性、资料待补项；
- 中性风险提示和经营改善建议；
- 固定数据来源说明：`本报告仅使用客户主动填写及授权上传材料；未调用外部个人信息查询接口。`；
- 报告使用边界和第三方数据提供授权说明。

客户不可查看：

- 银行名称、合作渠道、产品名称、产品编码、额度、利率、期限；
- 进件产品候选、匹配度、准入规则、规则表达式、命中数量；
- 内部评分、内部标签、员工备注、服务策略和渠道优先级。

### 1.2 员工视角：内部经营咨询与渠道服务报告

公司员工可在客户经营分析基础上查看：

- 客户画像核验状态和内部证据等级；
- 经营问题优先级、电话/来访访谈问题和改善动作；
- 合作银行/担保/保函等渠道清单；
- 可能适配的进件产品、匹配依据、缺失材料、渠道限制和下一步服务动作；
- 员工跟进记录、责任人、复核日期和内部风险提示。

员工视角只用于公司内部开展服务，不等于银行审批结论。员工对客户沟通时，应将内部产品和渠道信息转化为“材料准备、经营改善、办理路径说明”，不得承诺必然准入、审批、额度、利率或成功率。

## 2. 权限矩阵

| 功能/字段 | 客户 CUSTOMER | 公司员工 STAFF | 后端控制 |
|---|---:|---:|---|
| 客户经营分析 | 可见本人 | 可见有权限客户 | `reportDiagnosis` 客户校验归属；员工按内部范围 |
| 报告固定数据来源说明 | 可见 | 可见 | 报告详情固定展示 |
| 内部画像与员工建议 | 不可见 | 可见 | 仅 STAFF 身份返回 |
| 银行/担保合作渠道 | 不可见 | 可见 | 新增内部报告接口仅 STAFF |
| 可能适配进件产品 | 不可见 | 可见 | 客户 DTO 不返回 |
| 准入规则与规则日志 | 不可见 | 可见 | `ruleLogs` 仅员工详情返回 |
| 内部评分/匹配度/银行覆盖 | 不可见 | 可见 | 客户 DTO 不返回 |
| 报告列表跨客户检索 | 不可见 | 按员工权限 | 客户强制本人 |
| 内部报告导出/分享 | 不可见 | 仅授权员工 | 导出接口必须复用 STAFF 鉴权 |

“员工”必须以服务端登录态 `userType=STAFF` 为准，不能使用前端角色字段作为授权依据。离职、停用或权限撤销后，员工不再可读取内部视角。

## 3. 页面结构

### 客户页面

`经营分析摘要 → 数据依据 → 多维经营分析 → 重点发现 → 改善建议 → 数据来源与查询说明 → 使用边界`

页面不得出现“银行覆盖、命中产品、准入、匹配度、内部评分”等词。

### 员工页面

`客户经营摘要 → 画像核验 → 多维问题定位 → 合作渠道 → 可能适配的进件产品 → 材料缺口 → 服务话术 → 跟进计划 → 内部风险提示`

员工页的产品和渠道区块必须有“内部使用”标识；复制、导出和分享动作应保留员工身份、时间、报告编号和用途日志。

## 4. 数据分层

| 数据层 | 典型字段 | 客户 | 员工 |
|---|---|---:|---:|
| L1 客户经营事实 | 经营期间、收支、开票、纳税、流水分类 | 可见脱敏后的经营结论 | 可见原始依据和明细入口 |
| L2 经营分析 | 趋势、集中度、资料完整度、改善建议 | 可见 | 可见 |
| L3 内部画像 | 内部评分、画像标签、服务优先级 | 不可见 | 可见 |
| L4 渠道/产品 | 银行、担保、保函渠道、候选进件产品、匹配依据 | 不可见 | 可见 |
| L5 审计与权限 | 规则表达式、命中日志、查看/导出日志 | 不可见 | 仅按授权可见 |

## 5. 员工服务使用规范

1. 先解释经营事实和材料缺口，再介绍可能的服务路径。
2. 产品仅作为“可能适配、待核实、需以机构审核为准”的内部参考。
3. 向客户转述前，隐藏产品编码、匹配分数、渠道排序、内部评分和规则条件。
4. 涉及向银行或其他第三方提供资料时，单独确认接收方、目的、范围、方式和期限，并取得对应授权。
5. 客户未补齐材料时，内部报告状态应为“待核验”，不得升级为确定结论。

## 6. 验收清单

- [ ] 客户账号调用 `/api/mini/report/{reportNo}/products` 返回无权限。
- [ ] 新增内部报告接口只接受服务端登录态 `userType=STAFF`。
- [ ] 现有渠道合作端接口、菜单、权限和返回内容没有发生变化。
- [ ] 客户详情响应不含银行、产品、准入、匹配统计和规则日志字段。
- [ ] 员工详情响应可读取内部字段，但仅限服务端 `STAFF` 身份。
- [ ] 客户与员工都能看到固定数据来源说明，且文案与实际外部调用状态一致。
- [ ] 内部导出、复制和分享记录员工身份、用途和时间。
