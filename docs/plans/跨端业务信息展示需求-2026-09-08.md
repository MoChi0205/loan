# 跨端业务信息展示需求

## 目标

小程序、H5、内部 Web 面向业务用户展示可理解的人、客户、事项、状态与日期，不展示系统生成的物理 ID、业务编码或单号。

## 强制规则

1. 审批号、报告号、线索号、工单号、奖励号、客户编码、员工编码、产品编码等只作接口参数、路由参数和行键，不进入业务界面可见区域。
2. 禁止范围包括列表列、详情字段、弹窗、搜索提示、确认文案、无障碍标签、导出文件名及“复制编码”操作。
3. 审批卡片与表格至少展示：提交审批人、审批事项、审批状态或意见、提交时间。
4. 报告统一命名为：`【客户姓名或企业名】【YYYY年MM月DD日】`。
5. 客户、人员、产品、机构名称缺失属于接口契约缺陷，应在后端 DTO 中批量装配；前端不得逐行查名称，也不得以编码兜底。
6. 技术审计与调试页面可按权限显示 traceId 等排障信息，但不得扩散到业务页面。

## 验收范围

- Web：审批、线索、公海、客户、工单、报告、奖励、产品、规则、策略、模板页面。
- 小程序与 H5：审批、报告、服务单、线索录入、客户档案、产品与“我的”页面。
- 自动扫描模板中的编码字段展示、含“编号/编码/单号”的提示文案及复制编码操作；同时人工检查名称和事项是否充足。

## 契约说明

隐藏编码不改变后端业务唯一键设计。查询、更新、删除仍按业务 code/no 定位，自增 `Long id` 继续只作数据库内部主键。
