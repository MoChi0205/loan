# 三端双视角报告全链路实施方案 V1

**三端定义：** 小程序、H5、Web 管理端。小程序与 H5 根据登录身份展示客户视角或员工视角；Web 管理端承载员工完整内部视角。

**本期边界：** 现有渠道合作端、渠道产品录入、审批流程、合作库接口、渠道报告及渠道可见范围全部保持不变，不纳入本次改造。本方案新增的“员工内部经营咨询报告”仍只允许公司员工访问，不改变任何已有渠道功能。

**目标：** 客户资料只采集一次，后端生成经营分析基础数据；客户身份读取合规经营报告，公司员工读取内部经营咨询、现有匹配结果和可能适配产品。

## 1. 目标主链路

```text
客户提交/上传材料
  → 授权记录
  → OCR/人工复核
  → 经营事实快照
  → 经营分析基础结果
       ├─ 客户报告快照 → 小程序/H5（仅经营分析）
       └─ 员工报告快照 → Web/员工小程序（经营分析+渠道+候选产品）
```

现有渠道合作与产品审批链路继续按当前方式向匹配引擎提供产品数据，本期不调整其接口、菜单、权限或状态机。

## 2. 当前需要打通的报告断点

1. 小程序/H5 目前在同一页面依靠角色条件展示，需要进一步使用客户/员工独立响应 DTO，避免内部字段进入客户响应。
2. Web 尚无完整的“员工经营咨询报告”页面，需要接入经营画像、匹配产品、材料缺口和服务建议。
3. Web `/api/admin/report/screening/{reportNo}` 详情接口没有传入当前用户执行员工角色和归属范围校验，应补齐与列表一致的数据范围。
4. 当前 `t_report_template` 是单模板模型，没有客户/员工受众字段；需要建立双模板或双快照，避免通过前端隐藏字段实现隔离。
5. 三端尚未统一报告编号、模板版本、材料版本和生成状态，需要建立同一报告主键下的双视角关联。

## 3. 后端改造

### 3.1 复用现有匹配结果

本期不修改渠道合作、产品审批、合作库状态机或 `PlanLoaderService` 的候选产品加载逻辑。员工报告直接复用现有 `t_screening_product`、银行产品、匹配分数和规则日志，新增的只是内部报告组织、展示和权限隔离。

### 3.2 双报告快照

推荐新增：

- `t_report_snapshot`：`report_no`、`audience_type`、`template_code`、`template_version`、`content_json`、`source_version`、`generated_at`；
- `audience_type = CUSTOMER | STAFF`；
- 唯一键：`report_no + audience_type`；
- 客户快照只保存 L1/L2 经营字段；
- 员工快照保存 L1-L5 内部字段及 `t_screening_product` 引用。

禁止先生成全量 JSON 再在前端删除字段。客户快照在服务端生成时就不包含银行、产品、准入、匹配度、内部评分和规则日志。

### 3.3 接口分离

| 接口 | 身份 | 返回内容 |
|---|---|---|
| `GET /api/mini/report/{reportNo}/customer-view` | CUSTOMER 本人、STAFF | 客户经营报告快照 |
| `GET /api/internal/report/{reportNo}` | STAFF | 员工内部完整报告 |
| `GET /api/internal/report/{reportNo}/products` | STAFF | 复用现有匹配结果形成的渠道与候选产品 |

现有 `/api/channel/**`、`/api/mini/product/**`、`/api/mini/partner-product/active` 等渠道合作相关接口不调整。

员工接口还必须执行数据范围：顾问本人客户、部门经理本部门、老板/运营/超管全量。详情、导出、附件、批量接口使用同一范围服务，不能只保护列表。

### 3.4 审计

记录内部报告查看、导出和复制：员工工号、报告编号、客户编号、动作、用途、时间、IP/设备信息。向第三方提供资料的授权记录与报告生成授权分开保存。

## 4. 三端前端改造

### 客户小程序与 H5（共用 `loan-mini`）

- 只请求 `customer-view`；
- 页面固定为经营摘要、数据依据、多维分析、重点发现、改善建议、数据来源与边界；
- 删除任何合作产品公共列表调用；
- 客户端代码中不接收内部产品 DTO。

### 公司员工 Web

- 新增“内部经营咨询报告”详情页；
- 页面包含经营分析、画像核验、合作渠道、候选进件产品、材料缺口、服务话术和跟进计划；
- 候选产品区标注“内部使用、待机构核验”；
- 导出使用 STAFF 专属接口和内部水印。

### 员工小程序

- 保留员工报告入口；
- 员工登录时请求内部接口，不与客户接口共用响应 DTO；
- 移动端展示精简的客户摘要、产品候选和下一步服务动作。

### 渠道合作相关页面

- 全部保持现状；
- 不改菜单、接口、字段、权限和交互；
- 不接入本期新增的员工内部经营咨询报告。

## 5. 实施批次与验收

### P0 报告隔离基础（1个开发日）

- 修复 Web 报告详情角色/归属校验；
- 固化客户响应 DTO 与员工响应 DTO；
- 增加 CUSTOMER/STAFF 双视角隔离测试；
- 渠道合作相关代码零修改。

### P1 现有分析与匹配结果聚合（1个开发日）

- 经营诊断、客户画像、材料状态和现有匹配产品按 `reportNo` 聚合；
- 不改产品来源、渠道合作审批或匹配规则；
- 为员工模板准备统一内部报告 DTO。

### P2 双快照与双接口（2–3个开发日）

- 建表和迁移；
- 客户/员工模板版本化；
- 生成 CUSTOMER、STAFF 两份快照；
- 提供客户和员工独立 DTO/接口。

### P3 三端页面（2–3个开发日）

- 小程序/H5 接客户视图；
- Web 和员工小程序接内部视图；
- 增加内部水印与查看/导出审计。

### P4 端到端验收（1个开发日）

- 客户账号：只能看到经营分析；
- 员工账号：看到经营分析、内部画像、合作渠道和候选产品；
- 非员工直接调用新增内部报告接口：返回 403；
- 渠道合作端原有功能和返回结果回归一致；
- 小程序、H5、Web 分别完成一次真实账号回归。

预计总工期：6–8个开发日；P0 完成客户/员工响应隔离，P2/P3 完成后实现小程序、H5、Web 三端双视角完整打通。渠道合作相关功能全程保持不变。
