## C. Web 功能现状与缺失（代码实读）

### C.1 阶段二 14 功能域实现状态
14 域在 Web **均有页面 + API 封装，无空占位、无目录缺失**。状态分布：**已实现(UI) 10 个 + 部分(UI) 4 个**。
> ⚠️ 大量"已实现(UI)"页调用的后端接口在《阶段二后端验收清单》标"未开始/空目录"（dashboard、report、blacklist、order、approval(download)、reward、report-template、短信管理面、配置向导 Step0-5、初筛闸门）→ 联调时将空数据/404，属**后端就绪度问题，非前端空壳**。

### C.2 Web 端「缺失 / 角色权限缺口」（核心问题）
1. **菜单完全静态、无角色过滤**：`layout/Layout.vue:268-341` `menuGroups` 硬编码，所有登录角色看同一套 6 分组菜单；未调用已存在的 `/api/admin/org/menu/tree`（仅 OrgCenter 配置弹窗用）。
2. **OPERATOR / SUPER_ADMIN / SUPER 三角色前端未建模**：`store/user.js:14-19` `ROLE_PERMISSIONS` 仅 BOSS/DEPT_MANAGER/ADVISER；`Layout.vue:259-263` `roleText` 仅三值。**与 D0-4 直接冲突**——分配审批"仅 OPERATOR/SUPER_ADMIN/SUPER/BOSS"无法在前端承载。
3. **ALLOCATION 分配审批入口缺失**：审批中心仅 PRODUCT / DOWNLOAD 两 tab（`views/approval/ApprovalCenter.vue:10-13`），无分配审批类型，也无角色可见性区分。
4. **权限守卫默认放行**：`directives/permission.js:8` `checker = () => true`；`store/user.js:90` 权限数组为空时一律放行 → 4 条 `meta.permission` 路由（audit/org/client/blacklist）对所有人开放。
5. **按钮/操作级权限未落地**：`OrgCenter.vue:411` `saveRolePermission` 的 `permissionCodes` 恒为 `[]`；`v-permission` 指令等同失效。
6. **孤儿视图**：`views/report/ReportCenter.vue`（277 行）未被任何路由/组件引用，死代码待接线。
