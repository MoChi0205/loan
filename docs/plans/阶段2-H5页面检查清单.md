## 三、H5 特有样式

### 通过项 ✅
1. **hover 全局块**：`App.vue` `@media (hover:hover)` + `button:not([disabled]):hover` + `.u-hover` 已 `#ifdef H5` 隔离，小程序端不命中，无编译风险。
2. **focus-visible**：`App.vue` `:focus-visible` 金色 outline（H5 隔离），AppListItem 自带 role/tabindex/keydown.enter → 键盘可达 ✓。
3. **条件编译隔离**：5 个页面（report/list、index、product/edit、match、order/list）的 `input:focus` 已包 `#ifdef H5`，小程序端无 `:focus` 残留（踩坑 02 已规避）。

### 问题
- **H1【P1】无响应式限宽，宽屏/PC 视觉崩坏**：
  - 机制：uni-app H5 将 rpx 编译为 rem，运行时按视口宽度设置根字号 `document.documentElement.style.fontSize = viewportWidth / 23.4375 + 'px'`（已在 dist 产物验证）；**视口越宽 UI 等比放大**（1280px 视口 ≈ 375px 视口的 3.4 倍）。
  - 现状：全项目**无任何 max-width 页面容器 / 桌面媒体查询**（grep 仅命中 badge/info-value 等小元素），PC 浏览器打开时卡片/文字/TabBar 全部放大拉满。
  - 位置：全局（所有页面 + TabBar）；建议在 App.vue 加 `#ifdef H5` 的 `@media (min-width: 768px) { uni-page-body, .page { max-width: 640px; margin: 0 auto } }` 类限宽。
  - 期望：H5 桌面端呈现「移动端宽度居中」的卡片式布局；TabBar 同步限宽。
- **H6【P2】hover 覆盖不完整**：`.u-hover` 仅挂载 home（promo/entry）、index（dev-panel/role-item）、auth（type-card）；mine 菜单卡（menu-card）、match 结果卡（result-card）、product 产品卡（prod-card）等可点卡片未挂载 → 桌面悬停反馈缺失（AppListItem 自带 hover-class 不受影响）。
- **H7【P2】focus 覆盖不完整**：auth.vue（field-input）、home.vue（bind-input）输入框无 `#ifdef H5` 的 `:focus` 高亮（其余 5 页已有）；`field-input:disabled` 等无碍。

## 四、微信登录 H5 降级

### 现状链路（已核代码 + 后端配置）
1. `pages/index/index.vue doLogin()` → `utils/wx.js wxLogin()` → `isH5Env()` 命中 `#ifdef H5` → **直接返回 `H5_MOCK_CODE='h5_dev_mock_code'`**（不调 uni.login）。
2. `api/auth.js loginByWx(code)` → `POST /api/mini/auth/login`。
3. 后端 `WxCode2SessionService.code2Session`：`wechat.mock=true` 时按 code 哈希生成 `mock_` 前缀 openid → 走 wxLogin 建档/登录。

### 问题
- **H2【P1】H5 正式登录通道不可用 / 不安全**：
  - `loan-service/src/main/resources/application.properties` 只有一份配置（**无 application-prod.yml 等环境区分**），`wechat.mock=true` **全局生效** → 生产 H5/小程序都用 mock openid，任何人均可用任意 code 登录（无真实微信校验，客户身份不可信、openid 不持久）。
  - `mini.auth.phone-compat=false` → 后端手机号验证码通道关闭；且前端 `index.vue` **没有手机号+验证码登录 UI**（`api/auth.js loginByCode` 是死封装）。
  - 期望：① 按环境拆分配置（prod 关闭 mock、配真实 wechat.appid/secret）；② H5 端补「手机号+验证码」登录 UI（对齐 `loginByCode` + 后端开 `mini.auth.phone-compat`）；③ 或接入微信 H5 扫码登录（需 manifest appid + 网页授权域名）。
  - 依据：小程序上线清单 §十六/§十七（微信合法域名/真实凭证）；utils/wx.js 注释「H5 预览不支持微信授权」。

## 五、H5 构建产物

### 通过项 ✅
1. `dist/build/h5/index.html`：`<title>企业贷款咨询服务</title>` = `manifest.json h5.title` ✓；viewport + `viewport-fit=cover` 条件注入 ✓；favicon `data:,`（避免 404）✓。
2. 产物 552KB，`assets/` 按页面/组件分 chunk（home/match/mine/report...css/js + AppXxx 组件 css/js + api 模块 js）✓；**CSS 无 rpx 残留（已全部编译为 rem）** ✓。
3. `vite.config.js` dev 代理正确：`^/api/(?!.*\.(js|mjs|ts|css|json|vue|...)$)` 负向前瞻避免误代理前端 `api/` 源码模块，rewrite `/loan${path}` → `localhost:8080` ✓（含踩坑注释）。

### 问题
- **H3【P1】H5 生产 API 地址为空**：`api/request.js` `#ifdef H5` 分支 `BASE_URL = ''` → 生产 H5 请求 `/api/mini/*` 打到**静态服务器同域**；若未配置同域反向代理（`/api → 后端 /loan/api`）则 404。期望：上线方案明确同域代理，或按环境注入完整 HTTPS BASE_URL。
- **H4【P1】SPA 路由 fallback + 子路径部署**：
  - `index.html` 资源为**绝对路径** `/assets/*`（无 `vite.base` 配置）→ 部署到子路径（如 `https://host/loan-h5/`）全部 404。
  - 路由为 history 模式（`/pages/home/home`），静态服务器需 SPA fallback（非文件请求回退 index.html），否则**深链 / 刷新 404**。
  - 期望：确定部署根路径；子路径部署时配 `vite.config.js base`；服务器配 SPA fallback。
- **H11【P2】manifest 顶层 `appid: ""`**：H5 侧 appid 空（小程序已填 mp-weixin.appid）；未来接微信 H5 扫码登录需补。
