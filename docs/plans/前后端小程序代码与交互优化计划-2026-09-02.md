# 前后端与小程序代码、缓存及交互优化计划

> 版本：v1.0-draft
> 日期：2026-09-02
> 适用范围：`loan-service`、`loan-gateway`、`loan-web`、`loan-mini`、知识库与测试资产
> 业务基线：D35（代码标准化）、D39（客户归属/审批）、D41/D42（JDK8 + Nacos `prd`）、D43/D44（集中回归与启动避坑）

## 1. 目标与边界

### 1.1 目标

1. 统一前后端分层、复用、查询、分页、业务编码、异常、日志、缓存、并发、幂等和权限实现，消除重复逻辑与无效接口。
2. 为稳定且读多写少的数据建立有证据的 Caffeine + Redis 二级缓存，明确 TTL、容量、失效和一致性策略；敏感、高频变化和强一致数据不盲目缓存。
3. 重新梳理 Web 与 H5/微信小程序的角色化菜单、权限、审批、公海/客户归属、工单、产品和报告交互，确保“看得到、点得动、结果可理解”。
4. 完成后端、Web、H5、微信小程序构建和全角色真实数据联调；一次性采集问题后集中修改，避免每个 Bug 单独重启。
5. 将新发现的性能、权限、启动和测试坑沉淀到知识库，形成下次可复用的测试门禁。

### 1.2 本轮不做

- 不修改真实 AppID、HTTPS 域名等上线配置（继续按 D33 放到最后）。
- 不切换 JDK 17，不启动本地 Nacos/MySQL/Redis；后端继续使用 JDK 8 + Nacos `prd`。
- 不在没有数据量、延迟或一致性证据时无差别增加缓存、锁、线程池或重试。
- 不删除历史文档、历史数据或现有功能；清理无用代码先建立引用证据和可恢复提交。

### 2.2 已定位的高风险/高收益点

| 编号 | 证据 | 影响 | 首批动作 |
|---|---|---|---|
| B01 | 多处 `selectById` 用于计划、模板、规则、奖励、邀请关联 | 物理主键与业务编码边界不一致，接口复用和数据迁移困难 | 逐处核对实体业务编码；按资源统一 Query/Repository，保留仅持久层内部主键使用 |
| B02 | `ApiPermissionService`、通知、短信、会话各自直写 Redis；无统一缓存失效协议 | key、TTL、序列化和失效策略分散，难以观测和跨节点一致 | 先定义缓存目录、key 版本、TTL、命中率指标，再接入少量稳定字典/菜单类数据 |
| B03 | `ProductQueryService` 已修复产品城市 N+1，但其他服务仍有列表后逐项补名称/关联查询 | 数据量增长后延迟和数据库连接占用线性上升 | 形成批量名称装配器，增加 SQL/RPC 次数断言 |
| B04 | 审批、工单、客户、产品存在多个页面各自维护 loading/error/empty/选项 | 交互状态和错误文案不一致，重复实现易回归 | Web 统一 `useTable`/远程选择器；小程序统一分页状态与 `AppLoadMore` |
| B05 | Web 菜单依赖动态树，审批/工单入口由多个页面跳转；小程序 TabBar 按角色差异较大 | 权限缺失时可能“看得到但点不动”或入口误导 | 建立角色×菜单×接口×动作矩阵，先静态校验再真实角色回归 |
| B06 | `ScreeningService`、`MiniProductService`、`MiniOrderService` 等仍有 TODO 或临时分支 | 功能承诺与真实能力不一致 | 按 P0 正确性、P1 可用性、P2 体验分批处理，禁止用前端假数据掩盖后端缺口 |
| B07 | 启动仍打印多轮 Nacos 配置初始化和 Dubbo Logo，AspectJ 初始化耗时明显 | 本地回归等待时间长，容易误判服务未启动 | 分阶段记录时间；只保留一套配置预加载链路，验证不破坏 `prd` 配置读取 |

### 阶段 2：缓存、日志、并发与启动优化（P1）

**目的**：只对有证据的热点读链路优化，并保持可观测和可回滚。

## 5. 启动与测试避坑规则（本轮强制）

1. 只用 `bash scripts/service.sh` 管理四端，禁止手写 `kill`、裸 `mvn spring-boot:run` 或外包后台任务。
2. 后端固定 JDK 8；Apple 芯片优先 `/Users/admin/Documents/developer/jdk8-arm64/Contents/Home`，用户指定路径的实际 Home 为 `/Users/admin/Documents/developer/jdk1.8/Contents/Home`。
3. 数据库、Redis、Nacos 均读取 Nacos `prd`；不启动本地替代服务，不把敏感配置写进脚本/文档。
4. 健康判定使用真实 HTTP：8080 直连 `/loan/api/auth/health`；8088 返回未登录 code 属于网关鉴权行为，不等于服务挂掉。
5. 远程网络探测使用真实协议握手或 HTTP，不使用不可靠的 `/dev/tcp`。
6. 一次性采集日志与错误后集中修改；后端冷启动可能数分钟，以健康接口和 `Started LoanApplication` 为准，不按固定秒数误判。
7. Maven/JUnit 预期异常堆栈不等于测试失败，必须以 `Failures/Errors/BUILD SUCCESS` 判定。
8. 业务 ID、用户 ID、工号、产品编码不得作为用户主位展示；接口仍按业务编码传输。
9. Web/小程序构建必须分别执行生产 H5 与 `mp-weixin` 构建；大 chunk/vue-router 警告要记录，但不能伪装成功能错误。
10. 任何删除、物理清理或契约推翻，先建立可恢复提交并向用户确认具体目标。
