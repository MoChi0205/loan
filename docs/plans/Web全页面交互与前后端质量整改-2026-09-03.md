# Web 全页面交互与前后端质量整改方案

> 日期：2026-09-03  
> 状态：执行中  
> 授权来源：用户明确要求检查并修复 Web 全部 Tab、按钮展示与前后端质量问题，按方案持续测试至阻断/严重缺陷归零。

## 1. 目标与验收边界

### 做什么

1. 修复侧栏菜单、顶部多标签和页面内标签的连续点击失步、旧页面残留、必须刷新才更新等问题。
2. 全量检查 Web 页面在常用桌面宽度下的页头操作、搜索操作、批量操作、表格操作列、下拉菜单和弹窗按钮，保证可见、可点、文案完整且权限一致。
3. 将共性缺陷收敛到 Layout、公共组件、composable、API 与后端公共服务，避免逐页复制补丁。
4. 对后端按证据审查分页、批量查询、N+1、物理 ID、幂等、并发、缓存、统一异常、限流熔断、traceId 和日志，不无证据堆叠缓存或锁。
5. 在 JDK 8 + Nacos `prd` 的既定联调环境下完成角色、页面、操作和接口回归，并把真实错误与修复结论回写知识库。

### 本轮不做

1. 不修改真实微信 AppID、HTTPS 域名等上线配置。
2. 不切换 JDK 17，不启动本地 Nacos、MySQL 或 Redis。
3. 不删除业务功能或历史数据；发现疑似无用能力先列清单与引用证据。
4. 不以“加缓存”代替性能证据；强一致、敏感和高频变化数据默认不进入通用缓存。

| W003 | 顶部标签无限累积，交互与渲染负担随页面数增长 | 严重 | 本地持久化已有 20+ 标签；Element Plus 标签栏参与每次更新 | 引入稳定的标签状态模型、数量上限/回收策略和可测的路由同步 |

| W007 | 表格操作组件内部 `overflow:hidden` 裁切长中文/下拉触发器 | 严重 | `AppTableActions.vue` 容器宽度受限时会裁掉“查看档案”“更多”等文案 | 已修复：取消内部裁切，由表格固定列和“更多”策略负责布局 |

| W009 | 渠道审批、渠道客户列表仍使用裸行按钮且未固定操作列 | 一般 | `approval/ApprovalCenter.vue`、`client/ClientProfile.vue` | 已修复：统一公共操作组件并固定右侧操作列，宽度 120px |
| W010 | 页面内 Tab 的旧请求可能晚返回覆盖当前 Tab | 严重 | 多个页面通过 `useTable` 切换 Tab；原实现无请求序列保护 | 已修复：`useTable` 增加 requestSeq，旧响应/错误/加载态不再覆盖最新请求，并新增回归测试 |
| B001 | 服务端没有统一 HTTP traceId 过滤器，网关与业务日志无法稳定串联 | 严重 | 仅 `Result.traceUuid` 字段和业务匹配 trace，未见请求头/MDC 过滤器 | 已修复：网关生成/透传 `X-Trace-Id`，服务端过滤器校验/生成并写入 Log4j ThreadContext，响应头回传 |
| B002 | Log4j2 仅按天滚动单文件，未按 biz/error 分流且无大小切分 | 一般 | `log4j2-spring.xml` 原仅 `loan-platform.log` + TimeBasedTriggeringPolicy | 已修复：新增 biz/error 文件、日期+100MB 滚动、30 天归档清理，并在 pattern 中输出 traceId |
| B003 | 编排模块/步骤管理接口仍暴露 `Long id` | 一般 | `StrategyTemplateController`、`AdmissionExecutionPlanController`、`RuleTemplateController` 的 module/step/field 路径仍为 `{id}`；实体暂无对外业务编码列 | 待数据库/契约迁移后处理；本轮保留内部 FK，避免破坏现有页面和存量数据 |

## 3. 分阶段执行

### 阶段 A：全量审计与自动化基线

- 生成路由、动态菜单、顶部 Tab、页面内 Tab 的一一映射。
- 扫描全部页面按钮、操作列宽度、固定列、搜索栏、弹窗、权限指令与用户可理解名称展示。
- 建立浏览器快速点击矩阵：侧栏连续点击、顶部标签往返、页面内标签、刷新、关闭、角色切换。
- 建立后端质量清单：分页/批量/单条、循环查询、`Long id`、写接口幂等、缓存与稳定性。

验收：问题项均有编号、文件/页面、复现或代码证据、严重级和处理阶段。

### 阶段 B：全局导航与布局公共层修复

- 路由作为页面与活动标签的唯一真值，标签点击不提前写活动态。
- 标签状态去重、校验、限量并安全持久化；无权限和不存在路径不进入标签。
- 页面内容与标签栏更新解耦，快速导航可取消旧导航/旧请求，不发生 DOM patch 竞态。
- 页头、搜索栏、批量栏和表格操作列建立统一响应式溢出策略。

验收：快速连续点击全部菜单及已打开标签，URL、面包屑、活动标签、页面标题始终一致；控制台 error 为 0。

### 阶段 C：逐页面功能与按钮修复

- 按路由逐页检查头部主按钮、搜索/重置、批量按钮、行操作、更多菜单、分页、页面内 Tab 和弹窗底部按钮。
- 权限按钮与后端角色/数据范围一致；无权限不展示，越权直调仍由后端拒绝。
- 人员、客户、产品、部门名称主显，编码仅作次要信息；禁止前端逐行补名称。
- 页面内 Tab 采用按需加载且避免旧响应覆盖新 Tab。

验收：每个可见按钮均完整、可达、状态明确；每个页面具备加载/失败/空态；页面内 Tab 首次及往返数据正确。

### 阶段 D：后端标准化与性能整改

- 同资源单条/批量/组合分页复用 Query 与 Service；批量限量、去重、单次查询。
- 清理对外物理 `Long id`，更新按业务唯一编码，禁止改写业务编码。
- 名称装配批量化并检查潜在 N+1；分页大小和排序字段白名单化。
- 重要写操作补幂等/唯一索引/CAS 或锁；明确事务与并发冲突结果。
- 缓存仅用于有证据的稳定读多写少数据，并具备 TTL、容量、双层失效、single-flight 和指标。
- 统一异常、限频、外部依赖超时/隔离/熔断、traceId、日志滚动与脱敏逐项核验。

验收：JDK 8 编译及后端全量测试通过；批量、分页、幂等、并发、越权、缓存一致性均有测试证据。

### 阶段 E：真实角色联动与收口

- 只用 `scripts/service.sh` 统一运行当前 backend/gateway/web/mini。
- 先集中完成静态修改，再统一重启；按七角色验证动态菜单、页面首屏 API、按钮、写操作与数据范围。
- 执行 Web 单测/构建、后端全量测试、H5/微信构建（若改动影响小程序契约）。
- 回写缺陷清单、验证矩阵、历史结论与启动避坑记录。

验收：阻断/严重缺陷为 0，控制台 error 为 0，所有构建和适用测试通过；一般问题必须有明确编号与后续处理入口。

## 4. 设计选择与回退

| 选择 | 理由 | 风险 | 回退 |
|---|---|---|---|
| 路由作为活动页面唯一真值 | 消除标签 `v-model` 与 RouterView 双向竞争 | 标签点击反馈依赖导航完成 | 回退到提交前 Git 基线 |
| 标签仅保存轻量导航元数据 | 页面组件缓存与动态标签数组同周期更新已出现真实竞态 | 返回页面需重新拉取数据 | 对确有昂贵状态的页面单独使用稳定缓存策略 |
| 公共布局先修、页面差异后修 | 一次覆盖按钮溢出和 Tab 共性问题 | 全局 CSS 影响面大 | 用视觉/宽度矩阵逐页验证，按选择器局部回退 |
| 性能措施按证据接入 | 避免缓存、锁和重试带来一致性及复杂度风险 | 审计周期更长 | 保留审计基线，分批提交 |
