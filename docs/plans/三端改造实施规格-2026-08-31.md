## 二、第 3 点澄清（守卫放行问题）

原问题「守卫放行是否改为'无 permissions 即拦截'」你回复「不清楚你说的」，说明如下：

- **现状（风险）**：`loan-web/src/directives/permission.js:8` 写死 `checker = () => true`，即**任何登录用户都能通过所有权限校验 = 等于没设防**。
- **推荐决策（deny-by-default，安全且不误杀）**：
  - 路由 / 菜单 / 按钮**声明了 `roles`/`permissions`** 且当前用户不满足 → **拦截**；
  - **未声明**任何权限要求 → **放行**（避免现有未接入权限的页面集体白屏）。
- 该决策已写入下方 ③ 规格，请确认是否采用（如同意即按此实现）。

### ③ 守卫 deny-by-default（`loan-web/src/directives/permission.js:8`）

```js
// 现状（危险）：const checker = () => true
// 改为：
const checker = (required) => {
  if (!required) return true;                 // 未声明权限 → 放行
  const user = store.getters.rolePermissions; // 当前用户权限集合
  return required.some(r => user.includes(r)); // 声明了且不满足 → 拦截
};
```
按钮级 `v-permission` 与路由 `beforeEach` 同步使用该 checker。

**前端待实现（`loan-mini`，`#ifdef H5` 分支）**：
