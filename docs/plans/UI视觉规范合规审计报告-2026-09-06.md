## 〇、先说结论

**用户反馈属实**：小程序/H5 当前实现与《设计系统规范》在「配色、视觉规范、组件收敛、交互状态」四个维度均存在系统性偏差，并非个例。09-05 差异核查聚焦"功能/接口闭环"，结论"已基本 Token 化、仅 mine.vue 残留 1 处 #fff"**低估了视觉层问题**——本报告在代码层新发现多类违规。

**总体健康分：12 / 20（Acceptable · 需显著整改）**。Token 体系本身设计优秀，但**页面层未严格执行**"禁止裸值 / 扁平化 / 组件收敛"三条铁律。

**最高优先级（P0/P1）问题**：
1. 调色板外裸色 `#a7f3d0`（home.vue）、`#534AB7`（TabBar.vue）—— 直接违反 Token 优先原则，且前者对比度存疑。
2. 装饰性渐变在 5 个页头/头像大量回潮（含 `match.vue` 径向金色光晕，属典型 AI-slop 发光反模式），违反"扁平化设计"强制基线。
3. `match.vue` 仍自定义 `.step-card` / `.upload-status`，未收敛到 `AppCard` / `AppTag` / `AppStepper`，违反"组件收敛"原则。
4. 组件普遍引用 `--color-*` 向后兼容别名而非规范 `--brand-*` / `--bg-*` 令牌，造成令牌混用。
5. Web 管理端硬编码色值普遍（报告模块单文件 16+ 处），且 Element Plus 默认主题未确认全量覆盖规范 `#3b82f6`。

## 四、详细发现（按严重度 P0–P3）

> 每条格式：**位置 · 类别 · 与设计规范偏差 · 影响 · 标准 · 建议**

### 4.1 配色 / Token 主题偏差

#### [P1] 调色板外裸色 `#a7f3d0` 作文字色
- **位置**：`pages/home/home.vue:453` `color:#a7f3d0`
- **类别**：Theming / A11y
- **偏差**：`#a7f3d0` 不在 `App.vue` 任何 Token 内，是浅薄荷绿；用作文字色时白底对比度远低于 4.5:1，违反"文字一律用 `--*-text` 无障碍变量"。
- **影响**：低视力用户几乎不可读；视觉与品牌体系脱节。
- **标准**：设计系统 §2.1 语义色 + §四 对比度；WCAG 2.1 AA 1.4.3。
- **建议**：替换为语义变量，如成功场景用 `var(--success-text)`；若为卡片内图标点缀色，改用 `var(--success)` 且仅作底色/图标，文字走 `--success-text`。

#### [P1] TabBar 硬编码蓝紫 `#534AB7` 与青 `#0E7490`
- **位置**：`components/TabBar.vue:66` `MATCH:'#534AB7'`；`:69` `MINE:'#0E7490'`
- **类别**：Theming / Anti-Pattern
- **偏差**：`#534AB7` 不在调色板（角色色板 7 色亦无此值）；`#0E7490` 等于 `--info-text` 但写成裸值而非 `var(--info-text)`。
- **影响**：tab 图标配色与品牌体系不一致；`#534AB7` 偏"科技紫"，与"瑞幸式专业单色"调性冲突。
- **建议**：`MATCH` 改用 `var(--gold)` 或新增令牌；`MINE` 改 `var(--info-text)`。全部 tab 色统一从 `:root` 令牌读取，禁止裸 hex。

#### [P2] 裸 `rgba(0,0,0,…)` 阴影（未用阴影令牌）
- **位置**：`pages/index/index.vue:451`（`rgba(0,0,0,.45)` 遮罩）、`pages/match/match.vue:880`（`rgba(0,0,0,0.18)`）、`pages/mine/mine.vue:448`（`rgba(0,0,0,0.05)`）
- **类别**：Theming
- **偏差**：阴影令牌基色为 `rgba(15,23,42,…)`（slate-900），此处用纯黑裸值；遮罩 `.45` 透明度亦裸写。
- **建议**：遮罩用 `var(--shadow-lg)` 语义或统一 `rgba(15,23,42,.xx)`；建立 `--overlay` 令牌。

#### [P2] `<switch>` 组件 `color="#0B1D3A"` 裸 hex
- **位置**：`pages/auth/auth.vue:96`、`pages/match/match.vue:244,248`
- **类别**：Theming
- **偏差**：虽值等于 `--brand-deep`，但写成裸 hex，未走令牌；小程序 `switch` 颜色属性不支持 CSS var，属平台限制，需在 JS 侧映射。
- **建议**：在 `data`/常量中定义 `BRAND_DEEP = '#0B1D3A'`（或统一从 `getComputedStyle` 读取），避免散落裸值，便于后续换肤。

#### [P2] 组件引用 `--color-*` 向后兼容别名，未用规范令牌
- **位置**：`AppButton.vue`、`AppCard.vue`、`AppTag.vue`、`AppTopBar.vue`、`AppEmpty.vue`、`AppIcon.vue` 等多处使用 `--color-primary` / `--color-card` / `--color-text` / `--color-border` / `--color-accent` / `--color-success` / `--shadow-card`
- **类别**：Theming（令牌混用）
- **偏差**：`App.vue:161-181` 明确定义这些为"向后兼容别名，TODO 全量迁移后可删除"；组件应直接用 `--brand-deep` / `--bg-card` / `--text-primary` / `--line` / `--gold` / `--success` / `--shadow-md`。
- **附加问题**：`AppTopBar.vue:88` `var(--color-text, #1a1a2e)` 回退值 `#1a1a2e` 与令牌 `#1E293B` 不一致（错值回退）。
- **标准**：设计系统 §一 Token 优先原则。
- **建议**：批量 `replace_all` 将 `--color-*` 映射回规范令牌；修正错值回退；迁移完成后删除 `App.vue` 别名区块。

#### [P3] 裸字号残留（少量）
- **位置**：`pages/mine/mine.vue`（4 处）、`pages/index/index.vue`（3）、`pages/home/home.vue`（2）、`pages/order/detail.vue`、`components/AppButton.vue`（2）、`components/AppTopBar.vue`（1）使用 `font-size` 在 `20/28/32/40rpx` 等非令牌档位
- **类别**：Theming
- **偏差**：字号令牌为 `22/24/26/30/36/44rpx`，上述值不落在令牌档。
- **建议**：并入 `--fs-xxs~--fs-2xl` 体系；若确需中间档，新增令牌（如 `--fs-coarse:28rpx`）而非裸写。

### 4.2 视觉规范（扁平化）偏差

#### [P1] 装饰性渐变回潮（违反"扁平化设计"强制基线）
- **位置**：
  - `pages/home/home.vue:350` 页头 `linear-gradient(145deg, brand-deep, brand-mid, brand-bright)`
  - `pages/index/index.vue:248` 落地页头同款 3-stop 渐变
  - `pages/mine/mine.vue:379` 个人资料头 + `:486` 头像 `linear-gradient(135deg, brand-deep, brand-bright)`
  - `pages/auth/auth.vue:264` `.type-icon-wrap.icon-active` 渐变
  - `pages/match/match.vue:855` 主卡 3-stop 渐变 + `:854` 径向金光
- **类别**：Anti-Pattern / Visual
- **偏差**：`overview.md` 已明确要求"扁平化设计：去除装饰性渐变"，且 `report/detail`、`report/list` 结果卡已改扁平——但**页头/头像级 chrome 未同步**，形成"报告页扁平、首页/我的页渐变"的视觉不一致。规范仅允许 `AppCard--accent` 用 2-stop 品牌渐变。
- **影响**：整体视觉语言分裂；渐变 + 金光显"AI 感"，与瑞幸式去 AI 感目标相悖。
- **标准**：设计系统 §一（扁平）+ `overview.md` 视觉优化结论 + impeccable `quieter`/反模式。
- **建议**：页头/头像改为**扁平**——深蓝 `var(--brand-deep)` 实底 + 白色文字（如"我的"页头），或仅 `AppCard--accent` 保留 2-stop 渐变；删除 `match.vue` 径向金光。对应调用 skill 的 **/quieter** 收敛视觉攻击性。

#### [P3] 骨架屏渐变（可接受但标注）
- **位置**：`components/AppSkeleton.vue:46` 加载微光渐变
- **类别**：Anti-Pattern
- **说明**：骨架屏 shimmer 渐变属合理加载态，非装饰，保留即可。

### 4.3 组件收敛偏差

#### [P1] `match.vue` 未收敛到统一组件（`.step-card` / `.upload-status`）
- **位置**：`pages/match/match.vue` 模板 `:85/:169/:254/:273` 用 `<view class="card step-card">`；`:265` 用 `<text class="upload-status">`；样式 `:709` `.step-card`、`:815` `.upload-status`（含 `.ok/.fail/.pending/.empty` 四态）
- **类别**：Component Convergence / Visual
- **偏差**：设计系统 §七 迁移表明文规定：`.card`/`.step-card` → `AppCard`；`.upload-status` → `AppTag`；`.flow-step`/`.steps` → `AppStepper`。`match.vue` 仍维护**自己的一套**步骤卡与上传状态样式，与 `AppCard`/`AppTag` 并行，违反"6 个基础组件覆盖 90%、禁止同类多套并行"。
- **影响**：步骤卡圆角/间距/状态色与全局 `AppCard`/`AppTag` 不一致；后续改令牌要改两处，设计债务累积。
- **标准**：设计系统 §一 组件收敛原则、§七 迁移表。
- **建议**：步骤内容卡改用 `<AppCard variant="default">`；上传状态改用 `<AppTag :tone="ok?'success':fail?'danger':'warning'">`；步骤指示器若需横向进度，接 `AppStepper`。对应调用 skill 的 **/extract**（收敛组件）或 **/normalize**。

#### [P2] 旧类名残留引用（report/list、product/list）
- **位置**：`pages/report/list.vue`（2 处）、`pages/product/list.vue`（1 处）仍命中旧类名模式
- **类别**：Component Convergence
- **说明**：需精读确认是真实使用还是注释；若为真实使用，按 §七 迁移表收敛到 `AppCard`/`AppListItem`/`AppTag`。
- **建议**：抽样核对后统一替换。

### 4.4 交互状态 / 无障碍偏差

#### [P1] H5 键盘可达未全覆盖（原生 view 缺 tabindex/role/keydown）
- **位置**：全局——所有 `<view @click>` 型可交互元素（如 `match.vue` 步骤卡、`mine.vue` 菜单项、`home.vue` 入口卡）
- **类别**：A11y / Interaction
- **偏差**：设计系统 §四 要求"H5 端所有可点击 view 补 `tabindex=0` + `role=button` + `@keydown.enter`"；`App.vue` 仅对 `:focus-visible` 与 `.app-focusable:focus-visible` 给焦点环。未加 `.app-focusable` 的 view 在 H5 键盘下**无焦点指示、不可 Tab 聚焦**。
- **影响**：键盘/读屏用户无法操作核心流程（匹配、报告、菜单），违反 WCAG 2.1.1 / 2.4.7。
- **建议**：交互 view 统一加 `class="app-focusable"` + `tabindex="0"` + `role="button"` + `@keydown.enter="onClick"`；或封装为 `AppClickable` 包裹组件。

#### [P2] 交互 6 态未逐项核验
- **位置**：页面级自定义可交互元素（非 `AppButton`）
- **类别**：Interaction
- **偏差**：规范 §五 要求每个可交互元素 6 态齐全（Default/Hover/Active/Focus/Disabled/Loading）。`AppButton` 已覆盖；但页面自定义卡/列表项仅部分有 `:active`/`:hover`，缺统一 Disabled/Loading 态。
- **建议**：复用 `AppCard is-tappable` / `AppListItem is-tappable` 的 `:active` 反馈；加载/禁用态走统一组件。

#### [P3] `prefers-reduced-motion` 仅 H5 生效
- **位置**：`App.vue:206-214`（标注 `#ifdef H5`）
- **类别**：A11y
- **说明**：微信 wxss 不支持该媒体特性属平台限制，已在注释声明；H5 已覆盖，可接受，标注为已知边界。

### 4.5 Web 管理端同类型偏差（并行发现）

> Web 端非用户主诉范围，但同口径扫描显示同类问题，建议作为下一轮整改输入。

#### [P2] 报告模块硬编码色值普遍
- **位置**：`views/report/ScreeningReport.vue`（16）、`Overview.vue`（28）、`ReportCenter.vue`（12）、`screening/ScreeningCenter.vue`（14）等内联 `hex`
- **类别**：Theming
- **偏差**：虽 `theme/index.js` 定义 `#3b82f6`/`#10b981`/`#f59e0b` 企业蓝规范色，但视图层大量散落裸 hex（图表、内联 style、状态点），未统一走 CSS 变量或 Element Plus 变量。
- **建议**：抽取报告模块语义色为 CSS 变量（`--rp-pass`/`--rp-warn`/`--rp-reject` 等），内联 style 引用变量。

#### [P2] Element Plus 默认主题未确认全量覆盖
- **位置**：`loan-web/src/theme/index.js`、`styles/index.css`
- **偏差**：Element Plus 默认主色 `#409EFF`；规范主色为 `#3b82f6`。需核验是否所有 `el-*` 组件（button/primary/tag）已重设为 `#3b82f6`，否则出现"蓝+亮蓝"双主色。
- **建议**：在 `theme/index.js` 用 `--el-color-primary` 覆盖并生成浅色阶梯；全局 grep `#409eff` 确认无残留。

#### [P2] 装饰性渐变背景 `AnimatedBg.vue`
- **位置**：`components/AnimatedBg.vue`（8 处 hex + `linear-gradient`）
- **类别**：Anti-Pattern / Visual
- **偏差**：管理端登录/落地使用动态渐变背景，属装饰性动画背景，与小程序"去 AI 感/扁平"调性不一致；若管理端定位为专业后台可保留，但需与小程序视觉语言对齐决策。
- **建议**：与产品确认管理端是否采用同一扁平语言；若保留，限制动效强度并尊重 `prefers-reduced-motion`。

## 五、系统性问题与模式（非个例）

1. **令牌执行双层分裂**：`App.vue` 令牌定义优秀，但"页面/组件层裸值"成普遍现象——根因是规范未在 CI/提交钩子中强制（无 `stylelint` 禁止裸 hex/裸 px 规则）。建议加 `stylelint-config` 规则 `color-no-hex`（除令牌定义文件）、`declaration-property-value-no-unknown` 拦截。
2. **别名债务未清**：`--color-*` 别名本应临时，却已成组件主流写法，反向固化。根因是迁移缺少"删别名"收尾动作。
3. **扁平化只改了一半**：报告页（详情/列表/匹配结果卡）已扁平，页头/头像 chrome 未同步，视觉语言不自洽。根因是按模块改、无全局视觉基线复审。
4. **组件收敛未闭环**：`match.vue` 自成体系，说明"6 组件覆盖 90%"未作为 PR 准入卡点。
