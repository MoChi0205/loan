## 二、修复方案（实施前确认口径）

### #1 线索释放归属公海
- **统一为「手动释放 → 公司公海」**，与客户侧手动回收（`ClientAllocationService.recycleClient(...)` 默认 `ENTERPRISE`）及自动回收口径一致。
- `LeadService.release()`：`seaLevel` 固定 `COMPANY`、`seaDeptCode=null`；保留「7 天冷却」。
- 前端提示文案保持「已释放到公司公海」。
- 兼容：历史 `sea_level='TEAM'` 且当前无部门可认领的脏数据，本次不做批量迁移（避免误伤团队池），由用户释放动作自然纠正；如需迁移另开脚本评审。

### #2 客户列表列宽
- 「客户标签」列 `min-width=180` → `width=110`。
- 操作列 `width=220` → `200`，`AppTableActions` 传 `:max-inline="3"`，让「查看档案 / 编辑档案 / 快速跟进」直接可见。
- 其余列宽不动，避免打乱已确认的列顺序。

### #3 统一弹窗下拉组件
- 新建 `components/AppSelect.vue`：包装 `ElSelect`，`inheritAttrs=false` + `v-bind="$attrs"` + 默认插槽透传，**调用方写法不变**。
- 打开时以最近的 `.el-dialog` 为 popper 边界：
  - `preventOverflow.boundary = dialogEl`（不超出弹窗左右/上下）；
  - `flip` + 依据上下可用空间自动选 `bottom-start` / `top-start`；
  - 动态 `max-height = clamp(120, 280, 可用空间)`，列表内部滚动；
  - 触发器（含 filterable 输入框）在弹窗表单内固定，不随列表滚动。
- **替换范围**：18 个页面中弹窗内的 68 处 `<el-select>` → `<AppSelect>`（保留 `<el-option>` 子节点与全部 attrs）；弹窗外的筛选条下拉不强制替换（无弹窗边界问题），但组件同样兼容。
- 全局 CSS：`.loan-app-select-popper` 使用 `--loan-popper-max-h` 变量控制高度，`.el-select-dropdown__wrap` 内部滚动。

### #4 日期筛选补齐
- 统一用 `AppDateTime type="daterange"`（D83 宽度规范）。
- 前端请求参数命名统一 `createdAtStart` / `createdAtEnd`（业务时间字段按页面语义，如短信 `sendTimeStart/End`）。
- 后端分页接口补参数 + `ge/le` 条件；**只加后端真实支持的过滤，不做前端假过滤**（大数据量页面禁止全量拉取后本地筛）。
- 本次落地 8 个页面；配置类无时间列页面（资源池配置/配额/规则等）不强行加日期。
