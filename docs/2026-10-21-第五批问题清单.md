# 第五批问题清单（2026-10-21 22:05，4 项）

> 来源：用户 4 张截图 + 文字（客户公海 / 我的客户 / 我的线索 / 线索公海）。
> 原则：代码实证。

## #1 客户公海看不到「认领」按钮

**根因**：`ClientProfile.ownClientActions` 里认领与分配是 **if / else-if 互斥**：

```js
if (hasPerm(CLIENT_ASSIGN)) { 分配归属 }
else if (hasPerm(CLIENT_CLAIM)) { 认领 }   ← 老板/超管两项权限都有，永远走上一分支
```

**修复**：改为两个并列 `if`——有分配权限显示「分配归属」，有认领权限同时显示「认领」。

## #2 我的客户看不到「释放回公海」

**根因**：按钮一直存在，但排在 actions **第 5 位**，而 `AppTableActions` 是 `:max-inline="3"`（前 3 个内联，其余收进「更多」）→ 释放被折叠，用户以为没有。

**修复**：把「释放回公海」提前到第 3 位（查看档案 / 编辑档案 / **释放回公海**），快速跟进与发起初筛进「更多」。

## #3 操作列占据大量列宽

**根因**：`LeadPool` 操作列是 `min-width="260"`——**唯一弹性列会吸收表格全部剩余宽度**。线索公海每行只有 1 个「认领」按钮，却占了整行剩下的空间（截图红框空白）。

**修复**：两个页面操作列都改固定 `width="240"`（ClientProfile 原 200 偏窄会挤压按钮，一并调到 240）。

## #4 业务 bug：释放线索后，客户仍留在「我的客户」

**根因**：创建线索时 `ensureClientProfile` 会同步创建客户档案（owner=录入人，`lead.clientProfileCode` 关联）；
但 `LeadService.release` **只改线索归属**，完全不动客户 → 线索回公海大家可领，「我的客户」里却还有这个人 → 两个列表口径分裂。

**修复（联动释放）**：

- `release` 增加 `LoanUser operator` 参数；线索释放成功后调 `releaseLinkedClient(clientProfileCode, staffCode, operator)`
- 联动条件（全部满足才释放客户）：
  1. 客户仍归属**释放本人**（已转交同事的不动，避免误伤）
  2. **无成交工单**（status=DEAL）且**无进行中预约**（REQUESTED/CONFIRMED/ARRIVED/SERVING）
- 满足 → 复用 `ClientAllocationService.selfRelease`（与客户侧手动释放同一套逻辑：清归属 + 公司公海 + 冷静期 + 记录）
- 不满足 → 客户保留，回传原因文案（"客户已归属其他同事，未联动释放" / "客户已有跟进或成交记录，未联动释放"）
- 客户释放异常 → 线索释放**不回滚**，提示用户去「我的客户」手动释放
- 前端：确认框明示联动范围；成功 toast 展示后端返回的联动结果

**为什么用 selfRelease 而不是重写**：客户释放涉及归属校验、回收记录、冷静期、通知等一整套逻辑，复用唯一实现，避免两套口径漂移。
