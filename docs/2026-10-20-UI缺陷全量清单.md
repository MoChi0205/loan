## 缺陷 1：日期筛选组件全站不统一（核心，用户反复提出）

**根因**（这次是真根因）：管理端并存了 **3 个日期组件**，能力重叠、宽度规格各写各的：

| 组件 | 使用处 | 宽度行为 | 问题 |
|---|---|---|---|
| `AppDateTime.vue` | 11 处 | width prop，缺省回落 `100%` | 筛选条里忘传 width 就会撑满整行 |
| `AppDateRange.vue` | 4 处 | 默认 260px，固定快捷选项 | 与 AppDateTime 的 daterange 功能重复 |
| `ServiceDateTimeRange.vue` | 3 处 | **硬编码 `width:100% + min-width:320px`** | 无法控制宽度，是历史遗留 |

18 处使用明细：
- `ServiceDateTimeRange`（3，都在 ServiceOperations.vue 表单内）：L219 / L229 / L274
- `AppDateRange`（4）：RewardList.vue:19、ApprovalCenter.vue:35/58/112
- `AppDateTime`（11）：OrderList:23/142、ProductList:216/238、ChannelProductWorkspace:65、AuditCenter:36、ServiceOperations:25/287、ClientProfile:50/59、ApprovalCenter:172

**方案（根因级收敛）**：
1. 以 `AppDateTime` 为唯一组件，补齐它缺的能力：`default-time`（datetimerange 用）、`time-format`、统一快捷选项（今日/近7天/近30天/本月）。
2. 筛选条统一规格：daterange 260px、datetimerange 360px、date/datetime 200px，统一高度 34px。
3. `AppDateRange`、`ServiceDateTimeRange` 的使用处全部替换为 AppDateTime，两组件标记废弃（保留文件但不再新增使用）。
4. 替换后 AppDateTime 缺省宽度：表单内（el-form-item 未传 width）保持 100%；筛选条显式传统一 width。

## 缺陷 3：菜单布局分配不合理

**现状问题**：
1. 「运营管理」组下 3 项（客户导入进度 / 资源池回收规则 / 认领设置）实为「客户/线索分配配置」，与「客户中心」语义更近；
2. 「认领设置」与审批中心「客户分配审核」业务同源，却分属「运营管理」与「审批中心」两组。

**方案**（需你确认，改动会动菜单结构）：
- 方案A：保留「运营管理」组，只补图标 + 明确组名「运营配置」，不动结构（改动最小）；
- 方案B：把「资源池回收规则 / 认领设置 / 客户导入进度」并入「客户中心」分组作为「分配配置」分区，删除「运营管理」组。

## 缺陷 5：认领设置缺「新增配置」+「筛选」

**现状**：
- 前端 `AllocationQuotaConfig.vue`：无新增行/删除、无筛选；仅 LEAD/CLIENT 两行固定渲染。
- 后端 `AllocationQuotaController.java`：`SCOPES` 写死 `LEAD / CLIENT`（L47-48），save 校验 `!SCOPES.contains(scope)` 直接拒绝其他 scope。

**方案（需你确认业务语义）**：
- 认领设置的「适用公海」维度当前就是「线索公海 LEAD / 客户公海 CLIENT」两个固定公海类型，业务上不需要无限新增行。
- 若要「新增配置」，需后端扩展 SCOPES 支持更多 scope（如按资源池 poolCode 维度），前端加新增行 + 筛选。
- 建议先确认：你期望的「新增配置」是指什么？（新增更多公海类型？还是别的维度？）
