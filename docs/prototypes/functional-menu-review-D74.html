「分配 / 认领 / 审批」功能与入口全清单

这些功能并未消失 —— 它们分处小程序与 Web 两端，逐个标出所在地与入口
功能所在端入口可用角色后端
客户查重 → 申请认领 / 申请分配 小程序 智能匹配页 → 命中已有客户后「申请分配给当前用户」；未命中则「创建客户并申请认领」 顾问 / 经理 / 运营 / 老板 / 超管；渠道禁入 POST /api/mini/client/{clientCode}/claim
公海认领 小程序 · 本轮新增 我的客户 → 公海 子页签 → 行内「认领」 员工；公司公海全员可认领、团队公海仅本部门 POST /api/mini/client/{clientCode}/claim（复用）
分配审批（归属流转审批） 小程序 审批中心（pages/approval/list，类型「分配」） 运营（独立 tab）/ 经理（本团队）/ 老板·超管（全部） POST /api/mini/approval/ALLOCATION/{approvalNo}/audit
审核中心入口 小程序 我的 → 审核中心（文案：无归宿客户分配申请 · 通过后归属流转） 员工 同上
客户分配（直接指定顾问） Web 管理端 Web 菜单「客户分配」；覆盖式落归属、不生成审批单 部门经理（本部门）/ 老板 / 运营 / 超管 POST /api/admin/client/{clientCode}/assign
客户公海（Web 版） Web 管理端 Web 菜单「客户公海」→「未分配客户」页签（申请认领 / 管理指定顾问） 顾问 / 经理 / 老板 / 运营 / 超管 Web 接口
团队客户 Web 管理端 Web 菜单「团队客户」（与「我的客户」独立展示） 部门经理 Web 接口
客户总览 Web 管理端 Web 菜单「客户总览」（全司） 老板 / 超管 Web 接口
释放本人客户回公海 小程序 · D75 新增 我的客户 → 行内「释放」（二次确认，告知进公司公海 + 冷却期） 员工（顾问 / 经理 / 运营 / 老板 / 超管，仅客户归属本人）；渠道不可见（只读 D50） POST /api/mini/client/{clientCode}/release
团队客户 + 回收进团队公海 小程序 · D75 新增 我的客户 → 团队 子页签 → 行内「回收」（本部门成员名下客户） 仅部门经理（本部门范围；跨团队由服务端拒绝） GET /api/mini/client/team
POST /api/mini/client/{clientCode}/recycle
结论：小程序侧从来没有「客户分配」这个菜单。它是原型 webMenus 里 Web 端 的菜单项（仅部门经理那一行有）； 小程序内对管理角色的提示是「管理角色请在 Web 管理端直接分配客户给指定顾问，无需发起认领审核」。
「公海认领」按 D74 决定已进小程序；「释放 / 回收」按 D75 已补齐，且按钮按角色权限展示： 释放 = 员工本人客户、回收 = 仅部门经理、认领 = 员工；渠道无任何写操作。
老板 / 运营 / 超管的回收仍走 Web（其落地为公司公海）；小程序内无「全司客户」选择列表，故不放开。
