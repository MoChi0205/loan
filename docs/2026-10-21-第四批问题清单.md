## #1 保存客户档案报 `Field 'submission_no' doesn't have a default value`

**现象**：客户档案编辑保存 → `DataIntegrityViolationException` → 前端弹"系统内部错误"。

**根因（双层，缺一不可）**：

1. **schema 文件与生产库不一致**：`db/loan-db-schema.sql:631` 写 `submission_no varchar(64) DEFAULT NULL`，
   但**生产库该列是 NOT NULL 且无默认值**。（该 DDL 本身还不自洽——索引引用了表里不存在的
   `client_profile_id` / `submission_id` 列，说明 schema 文件已落后于线上。）
2. **MyBatis-Plus 默认跳过 null 字段**：实体 `submissionNo` 为 null 时不进 INSERT 语句，
   于是 `INSERT INTO t_client_business_fact (client_profile_code, field_code, field_value, field_type, extract_time)`
   缺了 `submission_no` 列 → 数据库拒绝。

触发路径：客户档案编辑保存 → `ClientService.updateClientDetail` → `upsertEnterpriseFacts`（L527 insert）。
提交单流程（SubmissionService / SubmissionFactsMerger）写的是真实提交单号，不触发。

**修复（纯代码，不动生产库 DDL）**：

- `ClientService` 新增常量 `NO_SUBMISSION = ""`（档案维护来源的占位）。
- insert 时显式 `row.setSubmissionNo(NO_SUBMISSION)`，让列一定出现在 INSERT 里。
- 查询侧两处 `isNull(submissionNo)` 改为 `isNull OR = ''`：
  - `enterpriseFacts`（读档案事实，L488）
  - `upsertEnterpriseFacts`（upsert 前查 existing，L517）

**为什么必须两处一起改**：只改 insert 不改查询 → 空串行查不到，每次保存都插新行（重复数据）；
只改查询不改 insert → 依旧缺列报错。

**兼容性**：查询同时匹配 NULL 与 ''，历史数据（若有 NULL 行）不受影响；
提交单流程的真实单号行不被误匹配（非空且非 NULL）。

**验证**：`mvn -pl loan-service -am compile` → BUILD SUCCESS。需重启 loan-service 生效。

## 遗留隐患

`db/loan-db-schema.sql` 与生产库存在**结构性偏差**（不止这一列）。后续凡涉及 NOT NULL 列的 insert，
先核实生产库真实结构（从 Nacos 数据源查），不要拿 schema 文件当真理。建议找时间做一次
schema 文件与生产库的全面 diff 并修正文档基线。
